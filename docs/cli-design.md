# tao 命令与流程接入

本文定义拟实现的工具接口，落实 {need}`REQ_8D96CE7C86D6463194942315CB61B62B`、{need}`REQ_879A3065136F4F1993721F8840A0121D`、{need}`REQ_B5412B888E844FD8AA6F76B9B59C4806` 和 {need}`REQ_AD6954B59E45455287DB1A499FB7232F`。**当前尚无 tao 可执行程序，下述命令均为接口设计，不是可直接运行的使用说明。** 随包的 [流程操作规程](../plugins/tao-dev/skills/tao-dev/references/workflow.md) 规定 agent 的调用时机与当前回退行为。

## 一、区分三种操作

**流程操作由 skill 组织。** `clarify`、`design`、`plan`、`work`、`debug`、`review` 是需要理解语境的工作，不应伪装成运行一次确定性命令就能完成。`start`、`verify`、`status`、`resume`、`finish` 等流程操作可以组合 CLI 原语，但工具结果不替代需求分析、设计判断或人工授权。

对抗式与跨供应商审查仍由 skill、可用客户端或人工组织；当前不增加会隐式调用多个模型的 `tao review`。其报告作为证据输入，工具只检查声明的范围、模型信息、输入指纹和完成条件，不能从存在两份报告或两个 CLI 名称推导独立审查通过。

**tao CLI 执行可确定的动作。** 负责解析、编号、创建模板、校验、查询、执行已配置检查和保存证据；使用方可以在普通终端或 CI 中执行。初版不从 CLI 再启动一个 LLM，不依赖 issue 服务、客户端或 Sphinx 出版才能检查 Markdown。

**斜杠命令和 hook 是适配层。** 斜杠命令在客户端选择操作、传参并进入同一 skill 规程；hook 按已验证事件调用同一检查逻辑，不复制规则。不要假设两个客户端支持相同的 `/tao:*` 语法，也不要把交互命令字符串交给 shell 执行。

## 二、命令、输入与副作用

表中的 `tao` 代表受信任的项目局部入口。发布实现拟随 skill 提供 `scripts/tao.py`，由已确认的 Python 环境通过文件路径调用；可由项目任务运行器提供 `tao` 别名，不要求全局安装。不能因为 PATH 中存在同名程序就认定它属于 tao-dev。

| 拟议接口 | 输入与结果 | 副作用及实施顺序 |
|---|---|---|
| `tao doctor` | 项目根、配置、工具与 schema 能力；输出版本及支持的命令 | 首批；只读，不安装依赖、不修复配置、不主动试跑构建 |
| `tao id new <TYPE>` | 支持的类型；生成 UUIDv4 ID 并检查当前索引和退役记录是否重复 | 首批；只输出 ID，不登记新条目或创建业务状态；尚无正式 profile 的类型明确拒绝 |
| `tao check [PATH...]` | 检查文档语法、结构、日期、ID、引用、任务；输出定位与诊断 | 首批；源文件只读；路径限制诊断目标，不省略解析引用所需的定义范围 |
| `tao resolve <ID>` | 从当前源或显式导入索引找定义、退役信息与发布入口 | 首批；只读，索引不可用时不猜路径；生成站点前 URL 可为空并说明原因 |
| `tao start --slug <slug> --locale <locale>` | 创建一个变更计划及其 DOC／CHG 标识符；输出路径和 ID | 模板阶段；修改项目文件和日期序号登记，排他创建，不覆盖既有内容 |
| `tao retire <ID> --reason <text>` | 展示条目及引用影响，按约定移除正文并登记退役 | 模板阶段；默认预览，显式 `--apply` 才写入；保留其他人工内容，错误时不留下半迁移状态 |
| `tao status <CHG-ID>` | 汇总任务、依赖、未决项及证据新鲜度 | 证据阶段；只读，不能因读状态而勾选任务；没有相关信息就返回未知 |
| `tao verify <CHG-ID> --profile <name>` | 执行项目配置中该 profile 的检查，保存每项真实结果和受检输入指纹 | 证据阶段；执行子进程并写报告，只运行已授权的项目命令，不调用 LLM 评分代替工具 |
| `tao checkpoint <CHG-ID> --from <file>` | agent 提供目标、决定、阻碍和下一步；工具附上实际状态与证据索引 | 恢复阶段；写变更的 `handoff.md`，原子替换，不自动提交或推送，不保存整段会话 |
| `tao finish <CHG-ID>` | 汇总格式、任务依赖、必需检查与当前证据是否具备收尾条件 | 证据阶段；只读，输出 `checks-satisfied` 或 `blocked`；不自动批准语义结论、勾选任务、合入或发布 |
| `tao docs build` | 使用选定出版依赖生成书籍、条目索引及永久链接入口 | 出版阶段；只写配置的生成目录，默认 `artifacts/book/`；不部署网站 |

未实施阶段的命令不出现在已发布能力列表中；禁止用返回成功的空实现占位。第一批先提供 doctor、ID、check、resolve，模板、证据与出版随后各自验收，不把尚未支持的 CHG／EVD 格式提前当作可执行输入。

## 三、公共执行契约

项目根由显式 `--project <path>` 或当前目录向上最近的 `.tao/config.toml` 确定；无配置时，仅 doctor、ID、check、resolve 可以在显式给定的项目根运行，不创建全局状态。内容检查枚举配置中的 include／exclude 范围，不使用 VCS 的跟踪文件列表代替实际文件范围。

Python 的文件枚举、Markdown AST 与 UUID 库是正确性路径。`rg` 可加速交互定位，但全文搜索不识别正式定义、示例、退役记录及分配竞争，不能决定 ID 是否可用；缺少 `rg` 或 `grep` 不影响语义结果。Sphinx 是可选出版依赖，VCS 是可选的修订与差异适配器；没有它们时仍能做基本结构和关系检查。

所有命令支持 `--format text|json`；JSON 仅输出机器结果，进度写 stderr，子工具原始输出写报告。公共结果包含 `tool: "tao-dev"`、`protocol_version`、`tool_version`、`command`、`status`、`diagnostics` 与 `outputs`；doctor 额外返回支持的 schema 与 `capabilities`，以便 skill 检查当前操作是否可执行。诊断记录遵循 [文档契约](document-contract.md)，消息可本地化，字段、规则号和状态值不变。

退出码统一为 `0`（该命令的确定性检查通过，可有 warning）、`1`（发现不满足条件的结果）、`2`（配置／工具故障、能力缺失，检查未完成）。`verify` 逐项区分 `passed`、`failed`、`not_run`、`not_applicable`、`stale`；失败或缺失必需检查不能合成通过。`finish` 成功只表示已记录的检查条件满足，语义审查和授权仍由流程确认。人工观察可登记为证据，但不能伪造工具退出码。

输入指纹覆盖相关代码、配置、规格、测试与工具／契约版本，记录枚举范围和排除规则；VCS 可用时附修订标识，但它不能替代未提交内容的指纹。运行前后比较受检输入，执行中发生修改时结果标记 stale，不用于完成声明。报告与指纹边界遵循 [产物保存约定](document-layout.md)。

写操作限制在项目内明确目录，解析路径和符号链接后仍不得越界；不修改插件缓存或用户全局配置。模板和编号写入需锁与原子操作；不自动修复有语义歧义的 ID、需求或引用。项目配置若新增可执行命令，先按已有授权与项目约定检查，不能因配置来自仓库就扩大权限。

## 四、skill 与客户端接入

进入开发、计划、恢复、验证或收尾工作时，skill 按 [流程操作规程](../plugins/tao-dev/skills/tao-dev/references/workflow.md) 读取当前需要的上下文。文件或条目变更后检查结构；实施后验证行为；新会话先核实现状；完成声明前检查证据时效。命令是这些动作的执行方式，不以命令名替代动作本身。

发现受信任入口后调用 doctor，并核实工具标识、协议版本和操作能力；入口不存在时不尝试 PATH 中的其他 `tao`，不自动安装。已有项目的构建、测试和查询工具可以作为当前回退；记录未自动校验或缺失的保证，不能把人工查看报告成 tao check 通过。需要依赖缺失保证的部分保留未验证，独立可做的工作继续。

Codex CLI 与 Claude Code CLI 使用各自原生 skill 选择方式，必要时增加斜杠命令包装。两端试验只在隔离项目或单次调用内生效，直接使用已配置的 `codex`、`claude`；具体隔离与验收规则见 [插件设计](plugin-design.md)。hook 实现后仅在文件变化、恢复或收尾等适用事件触发相应短检查；不执行长时间全量验证，不自动调用 start、retire 或发布动作。

## 五、验证与实现顺序

每个命令需正常输入和独立反例，不能只检查帮助文字或退出码。最小验收集包括：

- 含示例 ID 的围栏不注册定义；重复 ID、错误日期、悬空引用、任务依赖环产生确定诊断，移动文档不破坏全局引用。
- 无 VCS、无 Sphinx、无 `rg` 的环境仍能运行首批命令；未知 schema 和缺失入口明确失败，无全局安装回退。
- 删除最大日期序号后不复用；同一副本并发分配不同名称；离线分支冲突被检测，序号耗尽不溢出。
- 检查失败、工具缺失和执行中输入变化均不能进入完成状态；保存证据自身不会使代码指纹变化。
- 生成的稳定锚点、复制链接、移动后的旧入口与退役入口可通过浏览器和 HTML 检查验证。
- 同一个受测 skill 在两端实际读取规程并在正确阶段调用已支持命令；尚未实现的命令没有被调用或报告通过，试验之外不生效。

先实现并验证文档核心命令，再实现 CHG／EVD 模板和证据闭环，最后接入 hook 与出版。当前有 prompt 回退规程，不代表已有 CLI、分配器、模板或自动恢复功能；能力状态随真实验证更新。
