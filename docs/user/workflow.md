# 项目文档与持久计划协作

<!-- tao:section scope -->
## 适用范围

在目标项目加载 tao-dev skill，维护当前权威知识和跨会话项目进度。tao 不编排通用开发流程；agent 自行管理执行，并根据真实成果更新项目材料。安装见 [客户端接入](clients.md)。

<!-- tao:section steps -->
## 按知识需要协作

| 输入示例 | 文档结果 |
|---|---|
| 使用 tao-dev，说明导出取消的行为与验收，复用现有规格。 | 更新同一规格中的行为、边界和验收；只有确有新知识归属时才创建文档。 |
| 核对取消方案的设计与规格是否一致。 | 语义审查目标覆盖、状态、接口、失败路径和取舍，列出有依据的发现与未知项；格式通过不代表语义正确。 |
| 这项工作需要多人跨会话协作，维护一份成果计划。 | 复用或创建持久 plan，以可验证成果组织任务、依赖和范围，关联现有依据。 |
| 查询当前计划，依据实际成果更新剩余工作。 | status 只读当前记录；agent 另行核对文件与实际结果，在授权内回写同一计划，不把查询当执行。 |

小改动可以只更新适用文档，不要求 spec、design、plan 三件套。需要跨会话、多人协作或持续跟踪的工作保留项目计划；CLI new 只生成骨架，不代写规格、选择方案或组织执行阶段。

## 持久进度与临时步骤

计划任务描述可验证成果，例如“取消后不再产生输出，并覆盖取消与完成竞争的验收”，而不是“读文件、调用工具、写代码”等客户端临时步骤。默认把任务内联到 plan；任务较多时通过 tasks_doc 唯一关联一份附件，不能同时维护两份任务集。

客户端 task list 可以帮助 agent 执行，但不成为第二份项目进度源。agent 根据真实产物和已执行检查更新任务、阻碍及计划 verification 摘要；未完成部分保持可见，不能因临时步骤结束就勾选成果任务。status 不运行检查、不修改记录、不推荐下一开发动作。

更换会话或客户端后，读取同一 plan/tasks 及相关规格、设计，核对实际文件与验证适用范围，再决定执行步骤。多个计划时明确目标，不按文件时间猜测；缺临时摘要不影响协作。已授权范围内的执行由 agent 自行管理，重大范围变化或未授权操作仍需用户决定。

## 结果与长期知识

任务全勾选只表示已记录的成果进度，不代表已验证、已审查或已交付。审查没有记录就是未知；文档结构用 tao verify 校验，代码测试与 lint 直接调用项目的 justfile、Makefile、manifest 或 CI，不在 .tao/config.toml 重复管理。记录实际范围、结果和限制；检查不代替语义审查或交付判断。

完成计划保留为变更记录；当前有效要求、设计、ADR 与操作知识更新原文档，保持 ID 和引用。详细 review/evidence 默认临时，需要独立长期引用时才显式使用 evidence profile 并进入 book；不改写历史失败或以新摘要冒充旧检查的新鲜度。合并、推送、发布或清理工作区需要相应授权，不自动执行。
