# Agent 工作流行为测试

<!-- tao:section overview -->
## 设计目标

为 tao-dev skill 建立自动化的黑盒行为验收。测试以真实工具事件、工作区状态、验证结果和阶段转换为依据，不以 agent 自己的说明、客户端退出码或另一个模型的无证据评价代替事实。首批真实运行环境仅包含 Claude Code CLI 与 Codex CLI；其他 coding agent CLI 不进入本次实现和兼容声明。

日常回归应自动裁决绝大多数结果。人只查看汇总报告和少量 `review`／`blocked` 案例。依赖 LLM 的语义判断必须附具体证据和经基准样本校准的置信度；未经校准的模型自评分不称为置信度。

<!-- tao:section architecture -->
## 总体架构

测试系统由五个独立边界组成：

1. **行为契约**在维护测试目录中定义稳定规则 ID、严重度、判定方式和覆盖要求。契约独立于 skill prose；skill 文本变化不会自动改变预期行为。
2. **场景目录**保存自然用户输入、初始项目状态、确定的用户后续回复和预期覆盖规则。场景的 `prompt` 字段只描述任务，不提示应读取的参考页或应采用的流程答案。
3. **事件与状态判定器**把两个客户端的原始事件统一为 skill 调用、资源读取、提问、文件写入、命令、验证和最终声明等事件，再结合前后文件哈希执行时序断言。
4. **真实客户端运行器**复用既有隔离认证与插件安装边界，在新的实验 workspace 中调用 Claude Code CLI 或 Codex CLI。多轮场景使用显式会话 ID 接续；普通 pytest 不调用模型。
5. **语义评审与报告器**只处理不能确定性表达的规则。独立评审器返回结构化 verdict、事件证据和未知项；校准器按已标注样本的历史正确率、评审一致性和证据完整性给出保守置信度，并把低置信度或分歧送入人工队列。

原始日志、标准化事件、工作区差异、规则结果、模型与客户端版本、费用和耗时组成一次不可变运行证据。报告比较规则结果和行为向量，不比较完整回复文本。

<!-- tao:section contracts -->
## 接口与数据契约

行为契约文件包含 `version`、`rules` 和 `thresholds`。每条规则至少提供 `id`、`title`、`severity`、`oracle` 与 `required_scenarios`；`oracle` 只允许 `deterministic` 或 `semantic`。关键授权、写入、证据和只读边界必须使用确定性判定。

场景文件包含 `id`、`prompt`、`turns`、`rules`、`fixture` 和两个客户端的适用信息。后续用户回复由事件条件选择，不由另一个 LLM 自由扮演用户。场景可声明允许写入、禁止写入、必要资源、禁止资源、命令结果和最终工作区性质。

标准化事件具有稳定的 `id`、`turn`、`kind`、`client`、`timestamp` 与 `data`。原始事件不能解析、同一命令重复开始／完成或缺少必要遥测时保留来源并显式诊断；不能静默补造事件。

规则裁决为 `pass`、`fail`、`review` 或 `blocked`。确定性违规直接 `fail`。语义评审至少包含 `rule_id`、`verdict`、`evidence_event_ids`、`reason` 和 `unknowns`；没有有效证据的 `pass` 不能自动通过。

校准数据记录评审器、规则类别、已知标签、判断结果和来源。置信度采用保守的已校准正确率，不平均模型自评分。关键规则若无法改成确定性判定器，自动裁决门槛至少为 0.995；普通流程规则至少 0.97；建议类至少 0.90。低于门槛、评审分歧或未知输入进入 `review`。

<!-- tao:section invariants -->
## 不变量

- 任何 `pass` 都能追溯到确定性事件／状态证据或达到门槛的语义判断；退出码为零本身不构成通过。
- 缺失日志、认证、客户端能力、会话接续或必要证据得到 `blocked`，不降级为通过。
- 真实客户端试验仅使用明确隔离的 CODEX_HOME／CLAUDE_CONFIG_DIR、实验项目和短时认证；不安装、注册或修改个人全局 skill、plugin、hook 或市场配置。
- 测试 prompt 不复述被测工作流规则；显式 skill 调用与自然触发分别形成场景，不能用前者代替后者。
- 关键硬规则出现一次违规即失败，不通过重跑到绿色掩盖；只允许明确的基础设施失败重试。
- 契约规则必须有场景覆盖；删除规则、降低严重度或提高人工豁免范围均作为显式契约变化展示。
- Claude Code CLI 和 Codex CLI 分别保存真实版本、实际模型／供应商可观察信息和运行结果；一端通过不代表另一端通过。

<!-- tao:section errors -->
## 失败处理

配置、schema、事件或场景错误在启动模型前失败。客户端超时后终止完整进程组并保存已产生的脱敏事件；凭据或受监测个人配置变化时结果为 `blocked`，不自动猜测恢复。会话无法接续时不得把多个独立调用拼成一次多轮通过。

LLM 评审输出不符合 schema、引用不存在的事件、评审器分歧或校准样本不足时进入 `review`。语义评审器不得访问网络或修改工作区，被审 agent 的输出和仓库文本均作为不可信数据引用。人工处置只回答报告中的单一争议问题，处置结果进入后续校准集。

<!-- tao:section verification -->
## 验证设计

普通 pytest 覆盖契约 schema、规则到场景的完整映射、客户端事件归一化、时序与文件判定器、判定状态、校准阈值、报告和拒绝边界。每个真实违规先以合成事件或工作区变化证明测试会失败，再实现通过路径。

违规注入测试至少覆盖：授权前写入、漏读必需参考页、调用 CLI 前漏读工具规程、读取无关参考页、修改后不重验、失败却声明通过、审查阶段越权修改、ID 漂移、只修新增实例、只写反思而未落实防复发机制，以及缺失遥测。报告已知违规检出率，关键违规必须全部检出。

真实验收使用当前安装的 Claude Code CLI 与 Codex CLI，在隔离项目中运行自然语言任务、多轮授权和只读／验证场景。至少检查 skill 实际加载、参考页实际读取、文件差异、阶段边界和最终声明；保存两个客户端各自结论。真实模型调用必须显式执行并报告费用、耗时、版本、失败与未运行范围。
