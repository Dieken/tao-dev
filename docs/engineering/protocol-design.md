# 协作流程与架构决定

<!-- tao:section overview -->
## 目标

以 [开发协议](../product/protocol.md) 为需求，以 [纯 skill 重构](project-skill.md) 为当前边界。skill 指导判断，文档保存知识，计划表达任务，确定性工具不持有流程状态。

<!-- tao:section architecture -->
## 主线与选择

new 依次形成 spec、design、plan；review doc 核对目标、契约、方案与任务；implement 根据唯一任务集实施；review code 对照需求检查代码、测试和失败路径。已有授权内连续推进，不要求每阶段批准。refine 更新同一权威材料，status 只读当前任务，continue 核对事实后恢复，handoff 显式临时保存摘要。每个动作给推荐与下一步选项，选项不是审批关卡。

局部明确且易撤销的改动复用已有知识，不为格式齐全生成新文档。跨模块或高后果变更增加真实调查、设计取舍和独立审查，而不是增加状态登记。重大范围、权限和不可逆决定仍由用户控制；沉默、工具结果和 AI 建议不构成授权。

重要提议独立比较收益、成本、必要条件和简单替代；事实可查就自行核实。调试遵循证据、可证伪假设、最小实验、修复和回归；事故可以先可逆止损。没有新证据时不重复同一尝试。

<!-- tao:section contracts -->
## 资料与协作

规格维护 REQ/UC，设计说明接口、数据、不变量和失败，长期取舍抽 ADR；计划引用依据并列可验证任务。内联或单一 tasks 附件二选一。并行前明确文件边界、共享契约和集成责任，集成者统一验证，不把分支局部结果当整体成功。

任务完成、格式检查、行为检查和审查分别说明。审查没有记录则未知；详细输出默认临时，长期结论合并到权威文档，计划只保留当前摘要。显式交接缺失不阻断继续。

<!-- tao:section invariants -->
## 保留的工程原则

控制复杂度但不机械拒绝有需求支撑的结构；以真实调用与失败路径审查，不用模型多数票代替证据；未验证不冒充通过。正式文档继续使用稳定 ID、正向关系和可导航的书籍，不新增审批、revision 或阶段字段。

<!-- tao:section verification -->
## 检验

覆盖小改动、跨模块目标、需求变化、中断恢复、多个计划与工具不可用。结构检查和实际 agent 行为分别验收；文档能构建不代表协作行为已被验证。详见 [行为验收设计](agent-behavior-testing.md)。
