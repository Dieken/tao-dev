# 文档协作与知识架构

<!-- tao:section overview -->
## 目标

以 [项目知识协议](../product/protocol.md) 为需求，以 [纯 skill 架构](project-skill.md) 为当前边界。skill 管理文档语义，文档保存知识，持久计划表达项目成果与进度，agent 自行管理执行，确定性工具不持有流程状态。

<!-- tao:section architecture -->
## 文档职责与选择

先查找当前权威材料，再按知识缺口创建或修订规格、设计、ADR、计划及指南，不按固定阶段生成文档。文档审查核对目标、行为、约束、方案与成果任务之间的一致性，不只检查格式。CLI new 仅生成计划骨架，status 只读进度，不指示下一开发动作。跨会话、多人协作或需跟踪工作维护持久计划；执行工具和客户端由 agent 依据授权自行使用。

局部明确且易撤销的改动复用已有知识，不为格式齐全生成新文档。跨模块或高后果变更增加真实调查、设计取舍和独立审查，而不是增加状态登记。重大范围、权限和不可逆决定仍由用户控制；沉默、工具结果和 AI 建议不构成授权。

文档应区分候选、确认决定与授权，说明重要取舍的收益、成本、必要条件和替代依据。本仓库维护者另遵循 [开发指南](development.md) 中的工程判断与调试原则；这些不是分发给使用方的通用开发规程。

<!-- tao:section contracts -->
## 资料与协作

规格维护 REQ/UC，设计说明接口、数据、不变量和失败，长期取舍抽 ADR；计划引用依据并列可验证成果任务。内联或单一 tasks 附件二选一，客户端临时任务仅是执行步骤，不能另成项目进度源。agent 开始或恢复工作时核对计划和真实产物，在实际成果、阻碍或范围变化后写回同一计划。多人协作明确修改边界、共享契约和集成责任，不把局部结果当整体成功。

任务完成、格式检查、行为检查、语义审查和交付分别说明。没有记录的审查保持未知；详细输出默认临时，计划保留当前摘要。完成的计划保留为变更记录，长期当前知识合并到规格、设计、ADR 或指南，新会话不依赖临时摘要。

<!-- tao:section invariants -->
## 不变量

正式文档使用稳定 ID、正向关系和可导航的书籍；项目进度以 plan/tasks 为准，不因客户端步骤完成自动勾选成果。没有证据不宣称验证通过，不用模型多数票代替语义依据。本文保留本仓库的协作设计，不把产品变成执行调度器。

<!-- tao:section verification -->
## 检验

覆盖小改动、跨模块目标、需求变化、中断恢复、多个计划与工具不可用。结构检查和实际 agent 行为分别验收；文档能构建不代表协作行为已被验证。详见 [行为验收设计](agent-behavior-testing.md)。
