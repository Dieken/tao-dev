# 检查按自己的输入范围复用，整份回执仍绑定输入全集

<!-- tao:section decisions -->
## 决策

```{adr} 检查按自己的输入范围复用，整份回执仍绑定输入全集
:id: ADR_20260920_YB4X14PK7D277PS7
:status: proposed
:links: REQ_20260914_0J68SDKV86ENKER2

<!-- tao:field context -->
**背景与备选：** `verification.inputs` 是整个策略共用的一个输入范围，回执也整体复用：任一输入变化使整份回执过期，下次调用重跑全部检查。项目把文档类或数据类检查接入策略时因此两难——把这些输入纳入范围，改一行文档就要重跑全部长检查；不纳入，该检查的结果又不随其真实输入过期。备选一是维持现状，由项目在两种失效中自选。备选二是为这类检查另设分类，其输入自动取受管理文档集合，但 PostToolUse hook 每次编辑后调用 `verify --only docs`，该路径的既有契约是不执行任何项目命令，把可配置命令引入文档分类会让 hook 执行仓库配置里的命令。备选三是让每项检查的输入范围同时决定它自身的过期判定，更精确，但需要另加“各项声明的并集必须覆盖输入全集”的约束来堵住无人认领的输入文件，且同一份回执内各行的范围不再一致。

<!-- tao:field decision -->
**选择：** 每项检查可声明自己的输入范围，该声明只决定本次是否重新执行它。整份回执仍绑定全局输入全集，任一输入变化仍使整份回执过期；重新执行时，声明范围内无变化且上次通过的检查复用上次的执行结果，其余照常执行。声明匹配的文件集合须是全局输入范围匹配集合的子集。复用时效由每项检查各自的实际执行时刻判定，不由整份回执的记录时刻判定。

<!-- tao:field consequences -->
**影响与后果：** 文档类与数据类检查可以进入策略，改动其输入不再牵动无关的长检查。代价是一项难以撤销的取舍：允许逐项复用之后，某项检查的输入范围若声明得比真实依赖窄，它会静默停止重跑而整体仍报通过。子集约束挡的是声明越界，挡不住声明不全；工具无法发现隐含依赖，声明的完整性由项目承担。作为补偿，策略、工具与环境指纹的变化仍使全部检查失效，不设逐项例外。时效必须逐行记录，整份回执刷新记录时刻不得使未重新执行的检查显示为新鲜，否则连续的无关改动会让久未执行的检查长期显示新鲜。保守语义保留了“一份回执对应一个确定的输入全集”这条可一句话说明的性质；回执已逐行保存输入摘要与执行时刻，日后确需逐项过期判定可在此基础上扩展，反向收回则是行为倒退。
```
