# 一个审查批次自身的记录不参与它自己的受检输入

<!-- tao:section decisions -->
## 决策

```{adr} 一个审查批次自身的记录不参与它自己的受检输入
:id: ADR_20260921_7GKEM95QP289V30G
:status: proposed
:links: REQ_20260914_0J68SDKV86ENKER2

<!-- tao:field context -->
**背景与备选：** 审查预留机制只排除本轮声明的新报告输出，而走完一轮审查还必须产出主审裁决、批次导航页与计划中的执行记录；这三样都在受检范围内，写下去输入摘要即改变，于是「最近一轮审查的输入仍为当前」这个进入 finish 的条件必然不成立。第 2 轮及以后尤其确定：裁决与批次导航在那时已经存在，而预留要求路径尚不存在，因此无法声明为本轮输出。该现象可直接观察：受检文件集合完全未变，仅输入摘要改变。备选一是维持现状，承认该闸门不可达并降级为提示，但这与项目「未运行的检查不记为通过」的立场相悖，等于保留一条形同虚设的门禁。备选二是改判闸门语义，改问「本轮结论对应哪个受检版本」而不是「登记后有无改动」，更贴闸门本意，但需要定义什么算实质改动，而该定义会与同一条需求中「历史报告变化仍使结果过期」相互拉扯。

<!-- tao:field decision -->
**选择：** 把不参与受检输入的范围从「本轮预留的新报告输出」扩到「本批次自身的记录」，即该批次目录下的文件，加上计划中记录本次执行的结果块。闸门语义不变，仍是「输入没变过」；改变的只是「本轮自己的产出」这个定义的完整程度。其他批次的报告、源码与未声明的新文件照旧使结果过期。

<!-- tao:field consequences -->
**影响与后果：** 完成一轮审查所必需的产出不再使该轮结论失效，finish 闸门因此可达，不必把一条已声明的门禁降级为提示。代价是同一批次内较早轮次的报告被改动后不再使该批次结果过期——这类改动此前由「历史报告变化仍使结果过期」覆盖，现在只剩 review-end 登记时记录的报告摘要可供事后比对，而没有任何检查会主动重新核对该摘要。接受这一点的依据是范围有界：它只放松同一批次内部，跨批次与源码侧的过期规则不变；而被放松的那部分，其完整性本来就由同一批人在同一轮里维护。若日后需要收紧，可在闸门处重新核对已登记的报告摘要，该数据已经保存，属于加法而非语义回退。
```
