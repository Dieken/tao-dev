# 开发与维护指南

<!-- tao:section scope -->
## 目标与边界

本仓库独立维护。先读 [AGENTS.md](../../AGENTS.md) 与 [技能源码](../../skills/tao-dev/SKILL.md)，不需安装到个人客户端。开发文档保留在 `docs`，产品分发只含 `skills/tao-dev` 的运行资源。

<!-- tao:section prerequisites -->
## 显式环境准备

开发需要 uv 与 Python 3.11–3.14。使用 `uv sync --no-config --locked --extra publication` 准备项目 `.venv`；所有 uv 调用加 `--no-config`，避免本机的镜像配置改写锁文件。依赖由 `pyproject.toml` 与 `uv.lock` 管理。读取技能、安装文件不要求准备出版依赖。

<!-- tao:section steps -->
## 常用操作

- `just check`：依次执行带覆盖率的回归、Ruff、受管理文档校验和锁定依赖导出核对。
- `just test`：运行带 Python 子进程覆盖率的回归，输出 tmp/tao/coverage/coverage.json。
- `just lint`：运行 Ruff 的 E9/F63/F7/F82 检查，输出 tmp/tao/ruff.json。
- `just docs`：复用文档校验门禁并构建文档书籍。
- `just package <新输出目录>`：调用 `scripts/package_skill.py --output` 生成纯技能包。
- `just bump-version [版本] [dryrun]`：默认提升下一个次版本；先用 `dryrun` 核对源码位置、历史记录和由 `uv lock`、`scripts/export_dependencies.py` 重建的锁文件、运行时清单及依赖清单。
- `just tao <参数>`：调用源码辅助 CLI；也可用 `.venv/bin/python skills/tao-dev/scripts/tao.py`。
- 回归：在显式准备的项目环境执行维护测试；运行范围与结果如实记录，不把未运行的客户端测试写成通过。

just 命令直接使用已准备的项目 `.venv`，不自动安装或同步依赖。测试、代码静态检查、超时和缓存由项目命令或 CI 管理，不放入 `.tao/config.toml`；本仓库每次调用均实际运行，CI 作业提供整体超时。每个 CI 检查作业在 `tmp/tao/evidence.json` 或同目录的专用清单中索引提交、环境、状态与实际存在的报告，并上传限期保留的临时产物；该清单不进入技能包或文档书籍，也不构成 tao 对交付的认证。真实客户端试验必须显式运行并限定在隔离项目内；当前 Codex 发现检查无需登录，不调用模型、不复用认证，也不修改个人安装或用户级配置。

## 文档与交付

长期要求、设计、ADR 与操作知识更新原文档，保留对象 ID；新增文档加入文档书籍，不强制每次修改新建规格、设计、计划。跨会话、协作或需要跟踪的工作以持久计划与任务为项目进度来源，客户端临时步骤不重复登记。智能体核对成果后回写任务、阻碍和当前验证摘要，详细输出默认保存在 `tmp/tao`，不自动建立审查报告或提交。实现集成后统一执行必要验证，记录实际范围、结果和限制；任务完成不表示验证或交付通过。完成计划保留变更历史，当前事实更新到长期知识文档。

## 本仓库的工程判断

以下原则用于维护 tao-dev，不随产品分发为通用开发规程：

- 先确认行为、边界与真实调用方，再选择能满足需求的简单设计；不为假设的未来需求预建抽象，也不机械拒绝有隔离、恢复或规模依据的复杂度。
- 重要提议比较收益、成本、必要条件与可行替代，区分候选、决定和授权；可查事实自行核实，知情决定后无新证据不反复争论。
- 模块、接口和状态保持明确归属，失败路径、安全边界及兼容性取舍进入设计；变更同步真实调用方与测试，不用压制异常或特例掩盖问题。
- 调试从证据与可证伪假设出发，做最小实验、修复与回归；事故可先可逆止损，没有新证据不重复同一尝试。缺陷修复应有对应行为验证。
- 小步集成，协作明确文件范围、共享契约和集成责任。按风险独立审查代码、测试、配置与文档，以可复核缺陷而非意见数量裁决；未经授权不启动模型试验。模型身份或供应商不可确认时不宣称独立或跨供应商审查完成。
- 模型检查仅约束声明模型、规则与边界，不证明实现正确。工具选择与维护代价见 [建模决定](decisions/formal-modeling-during-implementation.md)；格式、行为、语义审查与客户端实测分别报告。
