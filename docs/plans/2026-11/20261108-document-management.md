# 文档管理与持久计划

<!-- tao:section scope -->
## 目标与边界

tao 管理跨智能体、跨会话的项目文档及其内容约定，包括持久计划和实际进度；智能体与客户端负责开发执行、权限、调度和会话恢复。文档能力覆盖创建、更新、语义审查、结构校验、组织出版与退役，不仅管理格式。不强制每次变更都创建规格、设计和计划。

计划及其任务记录项目进度，是跨会话共享的唯一依据。跨会话、协作或需要跟踪的工作应维护持久计划，小改动复用已有文档。会话任务只记录临时执行步骤；实际结果、剩余工作、阻塞原因和验证摘要写回计划，不逐项同步操作。完成的计划作为变更记录保留，长期有效的要求和结论写入规格、设计和架构决策记录。

## 依据

复用并原位更新 [产品规格](../../product/project-skill.md)、[项目协议](../../product/protocol.md) 与 [架构设计](../../engineering/project-skill.md)，保留已有 ID 和引用。用户已确认产品边界及持久计划职责。

<!-- tao:section design -->
## 实现边界

技能根据文档需要选择参考材料，不编排通用开发流程。命令行工具提供计划骨架生成（`new`）、只读进度查询（`status`）、ID 与索引、退役、出版及文档校验，不返回下一步执行动作。`status` 只报告进度、待办与源文件位置，不复制验证正文或推断审查、交付状态；长期依据和实际验证结论留在文档原文。

分发包只包含智能体管理文档时需要读取的指令或运行时需要使用的资源；开发 tao 自身所需的工程文档留在顶层 `docs/`。项目测试、代码静态检查等由项目原有命令入口管理，不在 `.tao/config.toml` 保存或执行。客户端接入限于项目作用域，不修改全局配置，不启动真实模型会话。
