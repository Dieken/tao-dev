# 文档组织与产物保存

本文规定产品模板与出版实现的目标规则，落实 {need}`REQ_E58FFDB3015D4FC48E2481B83A5BFED8`、{need}`REQ_D3CC348D07B64AA188C079BE93B28E0A` 和 {need}`REQ_B5412B888E844FD8AA6F76B9B59C4806`。生成器与校验器尚未实现；现有项目先显式映射到既有目录，不自动迁移。

<!-- tao:section ownership -->
## 一、内容放在哪里

按信息职责定位，而不是给每个流程阶段都新建一份文件：

| 内容 | 权威位置与组织单元 | 不放什么 |
|---|---|---|
| 产品规格 | `docs/product/<capability>.md`，每个用户可命名的能力一份；含目标、范围、REQ／UC、约束 | 本次施工步骤、执行日志 |
| 系统与模块设计 | `docs/engineering/<system-or-module>.md`，每个已有系统或模块一份；含边界、状态、接口与依赖 | 复制规格全文、日常任务 |
| 跨变更的技术决定 | `docs/engineering/decisions/<slug>.md`，每个 ADR 一份；含背景、备选、决定、后果 | 临时实现过程；只影响本次变更的选择留在计划 |
| 变更计划 | `docs/changes/<yyyymmdd>-<seq>-<slug>.md`，一次交付目标一份 | 已在规格定义的需求全文、原始测试日志 |
| 用户说明 | `docs/user/<user-task>.md`，每个读者操作目标一份 | 内部研发任务 |
| 运维说明 | `docs/operations/<operation>.md`，每个部署、诊断或恢复操作一份 | 暂时实验记录 |
| 术语 | `docs/glossary.md`，项目共用；首次定义和同义词关系集中维护 | 复制各模块的全部接口定义 |

同一事实只在权威位置修改。变更分支或等价工作副本直接更新受影响的长期规格，计划引用 REQ／UC／ADR ID，任务说明本次差异及验证办法。用 VCS 差异评审代码与文档并共同集成；发布书籍绑定发布版本。不使用 VCS 的项目至少保留可还原的版本快照和输入清单。

## 二、变更文件的固定拆分规则

不改变行为、接口、权限、持久数据和运行约束的局部文案／格式修正，可以不创建变更文件，保留适当检查和交付说明。其余变更使用一份计划，依次包含：**目标与边界、规格引用、设计、任务、验证、未决问题**。无设计变化或未决问题时写明相应结论，不生成空附件。

默认计划内直接包含设计与任务。满足以下条件才拆，拆后原处只保留入口和一句职责说明，定义与 ID 随内容移动：

| 触发条件 | 确定动作 |
|---|---|
| 单份计划超过 20 个正式 TASK | 将全部任务移到同名附属目录的 `tasks.md` |
| 设计部分超过 120 个非空源文件行，含图表和代码围栏 | 将设计移到同名附属目录的 `design.md` |
| 一个决定约束至少两个变更，或改变系统级接口／数据／权限契约 | 抽取为长期 ADR；计划保留 ID 引用 |
| 已确定两个同时执行的编辑任务会写同一部分 | 在开始并行前按各自拥有的子系统拆成命名附件，并明确各自唯一写入者；仅有“可能并行”不触发拆分 |
| 计划仍超过 300 个非空源文件行 | 先拆超限设计和任务，再把完整参考资料移成命名附件；不把单个 REQ／UC／ADR 拆开凑行数 |

这些是本项目为统一操作设置的默认阈值，不是行业质量标准。项目可在配置中覆盖阈值，不能每次由 agent 随意变更；不能靠压成长行绕过限制。既有文档不自动因新阈值重排：当前修改涉及超限部分时执行拆分，语义上不可再拆的条目记录有理由的例外。只有验证日志过长时移出日志，不拆规格来容纳日志。

附属目录去掉计划文件的 `.md` 后缀。例如计划为 `20260914-001-stable-links.md`，附件为 `20260914-001-stable-links/design.md`。只有实际生成附件时才创建目录；不强制每次产生 spec、design、plan、tasks 四份文档。

## 三、日期、序号与命名

长期文档用稳定的语义文件名；不加创建日期前缀。变更计划采用 `<yyyymmdd>-<seq>-<slug>.md`，如 `20260914-001-stable-links.md`。日期来自 `created`，`seq` 为项目内当天的三位序号 `001`—`999`，`slug` 使用小写 ASCII 单词和连字符。附件沿用同一前缀；修改或移动不刷新日期。序号属于变更文件名，不替代任何正式 ID，也不表达跨项目唯一性。

**不回填空缺需要保存已分配上限。** 拟议生成器在 `.tao/name-sequences.json` 保存每个日期已分配的最大序号，纳入 VCS；分配 `max(登记上限, 当前已存在最大序号) + 1`，从 001 开始，不查 VCS 历史。单纯查找“最小未用序号”会回填空缺；只查当前最大值也会在最大文件被删除后复用。一天超过 999 时明确报耗尽，不静默变成四位或伪造日期。

同一工作副本用项目局部锁、原子写入与排他创建防止竞争；失败允许留下序号空缺，登记上限不回退。扫描范围为计划文件及登记文件，Python 负责可移植枚举与语义检查；`rg` 仅用于可选的快速定位，缺少它时不改变结果，不依赖 `grep` 方言。工具尚未提供前由单个写入者按同一规则维护，不宣称已有并发保障。

跨分支或离线副本仍可能分配相同日期序号，集成时必须检测并调整其中一个显示文件名及路径引用，正式 UUID 不变。登记文件冲突不能仅取最大值便认为文件冲突已解决。它记录少量分配状态，不保存每个已删除文件的正文。若登记文件缺失且可能有删除历史，停止声称“不复用”，先恢复登记或显式重建分配基线。

## 四、报告与证据保存

```text
docs/
  index.md                         # 书籍入口与目录
  glossary.md
  product/                         # 长期规格
  engineering/                     # 系统、模块与决策
  user/
  operations/
  changes/
    20260914-001-stable-links.md    # 计划正文
    20260914-001-stable-links/     # 按需附件
      evidence/                    # 经挑选的持久证据及摘要
.tao/
  config.toml                      # 项目约定，纳入 VCS
  name-sequences.json              # 日期序号分配上限，纳入 VCS
  retired.jsonl                    # 按需：正式条目退役记录，纳入 VCS
  local/                           # 可重建的索引、锁及缓存，不纳入 VCS
artifacts/                         # 工具生成文件，默认不纳入 VCS
  <run-id>/                        # 每次执行独立，避免覆盖旧报告
    junit.xml                      # 测试结果
    coverage.json                  # 覆盖数据，也可有 HTML 目录
    diagnostics.sarif              # 静态分析结果
    benchmark.json                 # 基准测量
    stdout.log                     # 原始输出，也可含截图和跟踪文件
  book/                            # 生成的 HTML／PDF 书籍
```

文件名是示意，不要求工具统一生成这些格式；只保存实际产生的文件。`artifacts/` 默认通过项目所用 VCS 的忽略机制排除，不能因引用了路径就变成持久证据。CI 临时产物可过期，本地报告可以清理，不应作为长期完成声明的唯一依据。

交付时挑选必要的摘要和小型报告进入对应变更的 `evidence/` 并纳入 VCS；大型报告、视频、构建包可进入项目指定的持久产物库。证据清单记录关联 ID、受检输入指纹、命令与环境、结果、内容校验和、稳定位置及保存期限；不要保存凭据。未配置持久产物库时可以选择归档必要文件，不能只写一个即将过期的 CI 链接。

源文件参与的内容指纹应排除生成报告、证据记录自身和可重建缓存，否则每次保存报告都会令证据失效。排除范围必须明确，不能排除实际影响行为的代码、配置、规格和测试。清理不能删除仍被有效证据清单引用的唯一副本；无法读取或已过期的证据报告为不可复核，不继续显示通过。

## 五、本项目自举边界

tao-dev 内部文档按职责固定为协议、格式契约、术语、文档组织、插件设计和 [命令设计](cli-design.md)。协议维护 REQ／UC／ADR 和实施路线，专题文档维护精确规则，README 只负责导航。它们是长期文档，保留语义文件名，不为示范日期序号而重命名。

这里的目录、阈值和证据方案是产品设计。交付模板和脚本实现后，再验证中英文模板、拆分前后 ID、退役记录、并发分配和证据保存；不能以本文存在宣称功能已实现。
