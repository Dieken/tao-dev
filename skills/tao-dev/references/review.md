# 文档语义审查

审查文档能否准确表达目标、承诺、方案、操作或项目进度，而不只检查模板字段。结构校验不能代替语义判断；文档审查也不认证实现或交付。

## 范围与依据

确定实际受检文档、版本、原始目标、有效约束及关联资料。实现、调用方、测试和用户观察可作为核对来源；资料不足、来源过时或没有可还原快照时，注明结论的限制。

## 检查语义

- 规格：目标与范围是否一致，承诺是否独立、可观察且有真实来源，验收是否充分且没有悄悄增加或削弱需求。
- 设计与决定：假设是否有依据，边界、接口、数据、不变量、失败与恢复是否明确，备选、取舍与代价是否说明。详见 [正文写法](document-content.md)。
- 计划与任务：是否覆盖目标、描述可验证结果、表达真实依赖，是否只有一份任务集；记录的完成、验证与审查是否有对应事实，未知与限制是否明确。详见 [持久计划](planning.md)。
- 指南与 runbook：读者、前提、步骤、权限、副作用、失败处理和验证办法是否足够且与当前行为一致。
- 共同内容：术语、ID、关系和导航是否一致；是否有过时、矛盾、重复或失去权威来源的内容。结构通过不证明外部资料真实、链接内容正确或操作可行。

每项发现说明定位、违反的契约、条件、依据、影响及最小修正或求证方法；区分真实缺陷、未证实风险和非阻断建议，允许无发现。采用、不采用或未解决的理由应有原始目标、有效决定或可核实事实支撑；意见一致不能替代依据。

## 结论归属

报告实际范围、结论和未核实内容；审查不构成单独的受管理文档类型。结论与详细输出的归属见 [结果保存](planning.md#结果保存)，长期要求与决定的归属见 [文档归属](documents.md#文档归属)。
