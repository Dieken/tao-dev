# 确定性检查

`tao verify` 只检查受管理文档的结构、ID、关系与导航；不执行项目测试、lint 或构建命令。固定返回有效性、计数、删除检查覆盖与诊断，不提供 simplified/summary 或 dry-run 模式。文档校验本身只读，需要结果就实际校验；status 不运行任何检查。

## 项目命令的归属

测试、lint、类型检查、构建及其超时、缓存和报告由项目的 justfile、Makefile、package.json 或 CI 管理；不要复制到 .tao/config.toml。agent 读取项目既有入口，核对副作用与运行条件后，在授权内直接调用。tao 不发现、调度或缓存这些命令，也不为业务工具安装依赖。

.tao/config.toml 仅用于文档、语言、出版和项目内路径，见 [可选项目接入](project-setup.md)。已有 verification 配置应把 argv 及必要运行条件迁入项目原生命令入口，再移除整个配置表；旧配置会明确拒绝，不会静默忽略或执行。

## 解释结果

只声称实际运行的结果；项目工具若复用缓存，注明实际执行时间、输入范围与复用限制。旧输入的结果不能冒充新改动通过，缺工具或未运行不等于通过。输入变化按影响重验，不降低断言来隐藏失败。

计划 verification 保存当前简短摘要，详情放 temporary 或 CI 产物；这里的结果摘要不属于命令配置，应继续保留。任务勾选、文档结构检查、项目行为检查分别报告；内容与来源须按 [语义审查](review.md) 判断，源文档检查不证明外部事实真实，也不构成审批或交付认证。
