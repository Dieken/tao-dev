# 检查结果与临时产物

## 默认归属

长期要求归 spec，设计及重要取舍归 design/ADR，项目任务与当前验证结论归 plan。完成的计划是变更记录，长期当前事实仍回写各自权威文档。review/evidence 详情、命令日志、截图、输入清单与本地 book 放配置的 temporary（默认 tmp/tao）或 CI 产物，不作为长期受管理文档，不分配正式对象 ID 或进入 book。

计划 verification 合并更新同一范围的当前摘要：受检版本与范围、实际命令或观察方法、结果、未运行/未覆盖项和剩余限制。历史失败不能改写成成功，旧版本通过不能证明当前输入通过；临时日志消失不反转已经发生的结果，也不能再声称原始材料可查。

## 结论与来源

长期价值来自可复用的结论、约束、原因及其适用范围，不来自一份报告有齐全元数据。将核实后的发现合并到规格、设计、ADR 或计划；正文注明必要的受检版本、实际执行时刻、来源和未覆盖范围，不用文档编辑时间、ID 分配日或粗略覆盖分类代替。

保留语义审查与来源链接，但不建立 review/evidence schema、EVD 或审查批次。TASK.evidence 是普通 Markdown 链接，可指向计划验证章节或检查产物；链接的可用性与任务是否完成分别判断。项目或外部系统负责专项原始材料留存，tao 不因此把临时报告升级为长期文档。

## 临时摘要

用户请求临时总结时直接提供普通 Markdown 或对话摘要，无需专用命令，不注册 ID、不进入 book，也不能替代计划回写。客户端私有任务与临时材料不构成第二份项目进度；缺少这些材料不妨碍读取仓库中的计划和事实。只清理本事项归属明确且不被活跃操作使用的临时产物，不清空共享临时目录或删除用户文件。
