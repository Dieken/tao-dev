# 证据与产物保存

## 默认归属

长期要求归 spec，设计及重要取舍归 design/ADR，项目任务与当前验证摘要归 plan。完成的计划是变更记录，长期当前事实仍回写各自权威文档。普通审查详细输出、命令日志、截图、输入清单与本地 book 放配置的 temporary（默认 tmp/tao）或 CI 产物，不自动建立正式文档或提交。

计划 verification 合并更新同一范围的当前摘要：受检版本与范围、实际命令或观察方法、结果、未运行/未覆盖项和剩余限制。历史失败不能改写成成功，旧版本通过不能证明当前输入通过；临时日志消失不反转已经发生的结果，也不能再声称原始材料可查。

## 长期独立记录

仅有独立引用、审计、事故调查或可复现测量价值时，显式采用已有 evidence profile。保留已有有价值的正式 EVD 与来源，不因简化流程随意删除知识。inputs.fingerprint 表示可核对的受检输入，可用固定版本或快照引用，不必建立新的输入数据库。结果可为 unknown；实际执行时刻、记录时刻及未覆盖范围分别说明。采用 [报告写法](review-reports.md) 时仍遵守同一结构与导航规则。

evidence 保留 EVD、recorded_at 与 result：分别标识证据对象、记录时间和结果，不由任务勾选或文档状态推断。coverage 是可选粗分类，不要求填写 unknown；具体检查范围和未覆盖项写入 checks/findings，不能用 complete 代替范围说明。普通文档的 created/updated 可省略，不自动取 ID 分配日、文件日期或 Git 时间代填证据时间。

## 临时摘要

用户请求临时总结时直接提供普通 Markdown 或对话摘要，无需专用命令，不注册 ID、不进入 book，也不能替代计划回写。客户端私有任务与临时材料不构成第二份项目进度；缺少这些材料不妨碍读取仓库中的计划和事实。只清理本事项归属明确且不被活跃操作使用的临时产物，不清空共享临时目录或删除用户文件。
