# Agent 内开发流程

以用户结果为目标，以项目文档为长期知识，以计划任务为当前进度。动作是协作提示，不是 Python 状态机。不存在逐步审批、阶段登记、workflow 文件或 finish 动作。

## 授权与定位

先读取用户目标、项目约定、相关实现及已有 spec/design/plan。已有授权覆盖后续工作时连续推进，不为每个文档或任务再次请求批准；只有目标冲突、重大取舍、破坏性操作或范围外写入才请求必要决定。不得把建议、沉默或工具通过当授权。明确项目根；多个候选计划无法从上下文区分时列候选，不按修改时间猜测，不搜索全局安装或其他 worktree。

## 主线与下一步

`new（spec → design → plan）→ review doc → implement → review code`。按风险和已有材料复用或缩短路径，不为满足流程制造文档。支持 `refine`、`status`、`continue`、`handoff`，详见 [开发动作](workflow-actions.md)。这些是 skill 动作，CLI 仅提供确定性辅助。

每次动作结束说明实际结果、限制和下一步选项，给出推荐。例如文档准备后推荐 review doc，也可 refine；实现后推荐 review code，也可补验证。选项不构成必须停下等待的审批关卡；已有授权内直接执行推荐的下一步。未运行的验证或审查标为未知，任务全勾选仅表示实现进度。

## 输出纪律

结论优先、简洁可核实。长期知识直接更新规格、设计、ADR 或操作说明；当前任务和验证摘要只在计划维护一份。详细 review/evidence 默认留对话或忽略的临时目录，不自动建立报告、导航或提交。只在明确需要独立长期引用时采用已有 evidence profile。交接须显式请求，缺交接不阻断继续。
