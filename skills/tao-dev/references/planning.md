# 持久计划与项目进度

需要跨会话、多人协作或明确跟踪结果时使用 plan/tasks；局部小改动复用已有文档，不为形式齐全新增计划。计划描述一次事项的目标、依据、可验证结果和当前实际进度，不是强制开发阶段表。精确结构见 [文档规程](documents.md) 与 [plan 模板](../assets/templates/plan.md)。

## 记录目标与任务

先查找当前项目的相关计划，能覆盖同一事项就更新原对象，不重复创建。`tao new --slug <slug>` 只生成计划骨架；按实际需要补充目标、范围、依据和任务，不隐含创建 spec/design，也不授权后续操作。已有规格和设计用 spec_docs/design_docs 或正文链接引用；必要的局部取舍可留在计划，不复制长期正文。

正式 TASK 描述可核对的结果，而不是“读取文件”“调用工具”等客户端临时步骤。每项 verify 说明检查办法与预期结果；必要时 relates 关联 REQ/CHG，depends_on 表达真实依赖，不能用排列顺序代替。重要未知会影响目标、方案或验收时，先把求证结果写成任务，再关联依赖它的结果。

默认在 plan.tasks 内维护唯一任务集。确因规模或并行编辑需要拆分时，用 tasks_doc 唯一关联一份 [任务附件](../assets/templates/tasks.md)，附件与计划共享 CHG，移除原内联任务集，不复制 checkbox 或另设父任务完成状态。对象移动和修订保留 DOC/CHG/TASK ID；只有新增独立对象才分配新 ID。

## 读取与核对

`tao status [CHG|DOC|计划相对路径]` 只读任务计数、待完成项、计划验证摘要和推断进度；省略目标列出计划与尚无计划的规划材料，不运行检查、不写状态、不决定下一项执行动作。planning/pending/in_progress/tasks_complete 是材料推断，不是验证、审查或交付结论；review 为 unknown 时不能据任务数补出结论。任务集缺失、错绑或损坏时进度 unavailable，先说明材料问题。

以用户指定目标或已明确的计划为起点，读取计划、唯一任务集及相关权威文档，再核对当前文件、实际产物和可用结果。多个候选无法区分时列出候选，不按修改时间猜测。客户端原生任务是否跨会话保存因 CLI 和版本而异；即使可恢复，也不替代可共享、可版本控制的仓库计划。临时摘要只能辅助定位，不能覆盖当前文档和事实。

发现记录与事实冲突时说明依据，修正过时任务状态、结果摘要或权威知识；不能自动信任旧勾选，也不能机械改规格去迎合实现缺陷。并发编辑时以最新内容核对差异，保留他人修改；范围、决定或结果冲突须明确解决，不能以最后写入者覆盖进度。

## 回写实际结果

执行由 agent 自行管理；有实际结果后及时更新唯一任务集和计划摘要，不等会话结束才持久化。客户端任务可拆成临时操作步骤，但项目结果只回写 plan/tasks，不能把原生任务完成数当成项目完成数。

尚未完成或受阻的任务保留未勾选，在计划正文说明剩余结果、阻塞原因和解除条件；不要另造 checkbox 状态或把等待写成完成。跨会话需要的关键决定和依赖也须落到仓库材料，不能只留在客户端任务备注。

任务勾选仅记录所述工作结果已完成，不证明检查通过、独立审查完成或交付获认可。尚未执行的检查、失败和未覆盖范围分别写明；不能把预期结果写成观察结果，也不能因缺少独立 evidence 文件而制造形式门槛。verify 保留判定方法，实际观察和限制归 plan.verification；有可用独立证据时可附 evidence 链接。

verification 合并当前范围、版本、实际检查或观察、结果、审查情况与限制，不追加每次操作流水账。不知道就写未知；记录审查时区分实际审查者、对象和结论，CLI 不自动认证该文字。详情按 [证据保存](evidence-retention.md) 放临时目录或 CI 产物。用户要求临时总结时直接提供普通摘要，无需专用命令，也不形成第二份进度真相。

## 完成后的知识归属

完成计划保留为本次变更记录，不持续充当项目当前状态说明。将可复用的承诺、实际边界、长期取舍及操作限制更新到 spec/design/ADR 或指南、runbook；计划链接这些权威位置并保留当时范围与结果。保留原 ID 和有价值的引用，任务完成不自动退役文档，也不将文档 status 自动设为 accepted。后续独立事项使用新计划，长期文档继续维护当前事实。
