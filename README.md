# tao-dev · 协作开发之道

面向 AI 与人的协作开发 skill 项目，覆盖需求、交付、运行与持续改进。

当前是人可读的需求与设计草案阶段，尚未提供可执行 skill、正式校验器或出版站点。

## 阅读入口

1. [协作开发协议](docs/protocol.md)：项目目标、需求、流程、文档职责、设计取舍、验收用例和自举路线。
2. [Markdown 文档契约](docs/document-contract.md)：章节结构、全局 ID、条目、引用、任务格式和诊断约定。
3. [插件打包与运行环境](docs/plugin-design.md)：Agent Plugins 标准结构、平台组件映射和双 CLI 验收。

主协议目前同时承载需求与设计，二者通过条目类型和稳定 ID 区分；格式契约独立维护精确语法。暂不再创建内容重复的 spec、design 和 plan。

首批目标环境为 **Codex CLI 和 Claude Code CLI**。公共组件以 Agent Plugins 1.0.0 和 Agent Skills 为格式基线，agent、command、hook 按客户端原生扩展适配，两端分别实际验收。运行源码计划放在 `plugins/tao-dev/`，尚未创建或安装插件。

## 开发文档与分发边界

`docs/` 仅供 tao-dev 自身的开发、评审和维护使用。它描述产品需求、实现设计与验收依据，不属于安装给第三方项目的 skill 内容，也不应被运行中的 skill 自动加载。

未来分发内容中的 `SKILL.md`、运行参考、模板和脚本单独组织；根据已确定的需求提炼必要内容，明确对应关系，并通过测试检查一致性。发布采用明确的文件清单，不将整个开发仓库打包；运行材料不得依赖 `docs/` 或本地研究目录。这里的模板示例是设计材料，正式模板另行实现和验证。

开发文档维护当前目标、约束、设计理由和必要参考；对话经过、逐轮修改说明与临时检查流水不进入正文。一般修改历史由 Git 保留，仍有价值的取舍写入决策记录。

## 项目语言

tao-dev 以简体中文作为需求、设计和维护说明的权威正文；代码标识、文件名、schema 键、状态值、规则号和代码注释使用英文。后续 `SKILL.md` 初期采用中文及必要的英文术语，运行效果通过真实案例评估。

这一选择只适用于 tao-dev 自身。模板和生成器须尊重使用方的项目语言；显示文字可本地化，机器结构与条目身份不随语言变化。新文档的语言来自用户明确要求或目标项目约定，既有文档默认保留原语言。详细契约见 [本地化设计](docs/document-contract.md)。

## 自举方式

开发文档先采用拟议的元数据、章节键、条目 ID 和任务格式；再用正常及损坏样例实现最小校验器，随后以真实变更验证流程并接入出版与 agent 适配。自举用于检验产品设计，不改变开发文档的分发边界。

本 README 是阅读导航，不纳入正文 profile 的结构校验。新增文档类型与正式工具时，再扩展 schema 和检查范围；不预建空目录或自动安装 skill。
