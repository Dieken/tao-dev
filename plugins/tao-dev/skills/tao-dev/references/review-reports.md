# 正式审查报告写法

将审查结论保存为受管理交付文档时读取；对话反馈、临时分析和只读审查者返回的内容不自动建档。用户明确指定其他格式时遵循该格式并说明未做 tao 格式校验；项目已要求的正式记录不能以临时材料替代。

## 选择与填写

独立报告用 [review 模板](../assets/templates/review.md)，主审裁决用 [review-adjudication 模板](../assets/templates/review-adjudication.md)，均复用 evidence。共同元数据、五个固定二级章节、ID 和引用语法按 [文档规程](documents.md)；结果、记录时间与保留规则按 [证据保存](evidence-retention.md)。

- scope 说明范围，并单独记录实际执行时间及来源，未知时不猜测。
- inputs 区分当前源链接与受检固定版本；environment 记录实际审查者、供应商、模型、调用方式、强度、独立性及轮次，未知信息明说。裁决可用来源表汇总，不重复报告正文。
- checks 分别记录确定性检查与审查结论；Markdown 报告不能替代 [机器审查回执](review-receipts.md)。
- findings 用局部编号和严重性标识发现，写清定位、约束、触发、证据或待证假设、后果及最小改动或验证。严重性以项目约定为准，明确是否阻断；缺陷、风险、建议与已接受限制不混作同一结论。
- 裁决逐项链接来源报告和原发现编号，标明采用、部分采用、延期或不采用及依据。部分采用说明边界，延期说明条件，未解决项仍须保留。下一步影响只说明本次结论对后续工作的约束，不代表已获授权。

一条填好的缺陷：

```markdown
#### D1：中断后的导出保留半份文件

- **分类:** 数据完整性。
- **严重性与阻断条件:** 阻断；仅当下游按文件存在判断成功时成立。
- **定位:** [export.py](../../../src/export.py)，第 88 行。
- **约束:** {need}`REQ_20260918_EXAMPLE0000000A` 要求失败导出不留可见结果。
- **触发条件:** 写入第二块后进程被终止。
- **证据或待证假设:** 已用 SIGTERM 复现两次，保留 4.1 MB 残件。
- **根源:** 分块写入直接落在目标路径，没有提交点。
- **后果:** 下次增量导出跳过该区间，数据静默缺失。
- **最小改动或验证:** 写临时文件后重命名；回归覆盖中断点。
```

分类概括问题性质，供分批与聚合使用。根源写导致该问题的机制，与触发条件不同——触发是什么情况下暴露，根源是为什么会这样；未确认时写「待证」并说明缺什么证据，不推测。

备选解法是条件性的：确有代价不同的可行备选时写备选、推荐与理由，否则只写最小改动。为每条发现凑一组选项会稳定产出假选项，与不凑固定分析表的要求冲突。

同一问题在本批内或跨批复现时合并为一条，记录复现次数，并在裁决说明上次修复为何没挡住、本次是否把防护固化到类型、约束、回归测试或静态检查；固化方式见 [工程专题](engineering-practices.md) 的知识维护，不在此重述。

三级分类、表格和列表按实际内容选择，无内容的子分类删除；无发现时简述无发现及覆盖限制。小型裁决用一张处置表，需要时按主题拆分；长说明放相邻段落，不为套表省略条件或不确定性。

派发只读审查时提供所选模板、项目根与报告目录的关系；主 agent 负责分配文档 ID、保存和校验。跨报告引用保留原发现编号，链接来源报告或 findings 稳定章节；快照路径用于说明输入，不能当发布链接。保存后检查 schema、引用和管理范围，出版时再检查适用导航、实际 href 与目标锚点。

## 批次位置与命名

本规则仅适用于正式审查报告和裁决，不要求一般 evidence 改名。有计划时用 `<plan-stem>/reviews/<yyyymmdd>-<slug>/`；无所属计划、计划前或跨事项时用 `docs/engineering/reviews/<yyyymmdd>-<slug>/`。日期取批次开始的本地日期，后续编辑、移动或同批复核不刷新。

slug 概括本批评审的对象与目的，使用小写 ASCII 字母、数字与连字符，如 `export-contract`、`export-recovery-followup`。创建前检查整个批次目录；同一批继续原目录，同日不同批次或独立后续评审用更具体的 slug，不覆盖、不机械追加计数。文件保持以下形式：

| 内容 | 文件名 |
|---|---|
| 主审裁决 | `00-adjudication.md` |
| 独立报告 | `<NN>-<focus>-<reviewer>.md`，NN 为从 01 开始的两位编号；focus 和 reviewer 使用与 slug 相同的字符约定 |
| 批次导航 | `index.md`，使用 navigation profile |

NN 在同批内唯一，用于区分报告，不代表轮次或阅读顺序；同批复核若独立成文，使用新报告编号并在正文记录实际轮次。文件名中的 reviewer 只是便于识别的简称，实际身份、模型、供应商、方法与轮次以正文为据。导航统一按 [出版规程](publication.md) 维护；接入已有书籍时从上级目录挂接批次入口。命名和碰撞由作者核对，当前 schema 校验不强制这些路径模式。
