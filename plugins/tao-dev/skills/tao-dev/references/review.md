# 独立审查

正式审查时读取。日常方案取舍见 [工程规程](engineering.md)；本页维护审查方法、强度、范围与停止条件。

## 强度与来源

按改动后果选择，文档、配置或 prompt 的小改动也可能影响关键保证：

| 情形 | 默认方式 |
|---|---|
| 局部、低影响、易撤销 | 作者自查并检查受影响内容 |
| 普通功能或跨模块修改 | 在可用预算内采用独立上下文审查者 |
| 数据完整性、权限、难恢复迁移、破坏性契约、新增持久服务或关键争议 | 加强审查，优先不同供应商，挑战核心假设和复杂度 |
| 项目或用户有明确要求 | 按该要求，不用较低级别结果替代 |

跨模型指实际不同模型，跨供应商进一步要求来源不同；角色名、CLI 名或新会话不能证明差异。记录实际模型、供应商和调用方式，未知信息标为未知。所需能力不可用时采用可用的人或不同模型复核；无独立审查者时可完成自查，但须说明独立审查未执行。只有明确必需条件未满足才形成流程阻断。

## 审查方法

1. 固定受检版本，提供原始目标、有效约束和决定、实际产物、差异及检查证据；代码包含调用方和测试，文档包含相关实现和引用。输入记录按 [证据保存](evidence-retention.md) 处理。
2. 首轮任务不附作者自评或其他审查结论，待独立报告完成后再提供并对照；产物内的正式决定、理由与必要事实完整提供。
3. 检查边界、失败和恢复，寻找遗漏承诺与可删除的机制：spec 看场景与验收是否对应目标；design 质疑假设与备选方案，检查难以撤销的决定及其代价；plan／tasks 查隐藏决定、依赖与验证缺口；代码追踪可达失败序列，也查多余防护及恢复引入的错误。允许无发现，不凑数量。
4. 发现包含定位、违反的约束、触发条件、证据或待证假设、后果和解决该问题所需的最小改动或验证；区分缺陷、风险、非阻断建议及已接受限制。
5. 将意见视为待核实主张：先查契约、调用路径和已有保证，判断是否真实缺陷，再权衡修复收益与成本。用依据、复现、测试或基准裁决，区分契约误读、真实缺陷、已接受取舍与未证实风险；逐项记录采用、不采用、延期或未解决及理由。多模型一致不代替证据，意见未证实不等于已证明安全。

独立审查只读受检产物，复现写隔离临时目录；修改后确认旧发现仍适用，仅复核改动与影响范围。建议新增机制同样须解释收益和成本，不把偏好变成阻断。

## 范围、执行与停止

正式独立报告使用 [review 模板](../assets/templates/review.md)，主审裁决使用 [review-adjudication 模板](../assets/templates/review-adjudication.md)，均按 [文档规程](documents.md) 复用 evidence schema。位置与批次命名见 [文档组织](document-layout.md)，临时原始输出见 [证据保存](evidence-retention.md)。派发时提供适用模板、正式引用语法与受检项目根到报告目录的路径关系；只读审查者可以返回内容，由主 agent 分配文档 ID、整理与校验，不把未经整理的输出直接当正式文档。

正文条目引用使用 `{need}` 加完整 ID，不缩写；文件与其他报告使用相对 Markdown 链接，文件行号写在链接外，章节用稳定锚点。临时快照路径不能充当发布链接；当前源文档链接与受检固定版本分别记录，不能暗示当前内容仍等于受检输入。跨报告发现编号保留，并链接到来源报告或其 findings 稳定章节；局部发现编号不冒充正式 ID。提交报告前检查结构、引用、管理范围及适用的书籍导航，发布后检查实际 href 与目标锚点。

范围未明确时展示当前 feature/bug fix 的累计修改、全项目或自定义范围，并列基础版本、当前版本与工作区修改；已有明确范围直接采用。随后按已有偏好或用户选择安排串行／并行：小改动推荐一个审查者，普通 feature 推荐两个独立上下文分别关注需求／测试与实现质量；具体风险才加专项，并行最多三个。并行减少等待但增加总调用与去重工作。

审查授权不自动包含源文件修复，需报告写入时明确纳入范围；使用其他供应商需要相应数据与费用授权。已有开发事项按 [审查调度](review-runs.md) 保存预览、快照与轮次；无 CHG 的局部维护直接固定受检材料并保存报告，不为调用审查调度新建完整档案。

默认一次初审、修正后最多一次定向复核，项目已有时间、费用或轮次预算优先。扩大投入须有新证据、范围或预算决定；预算耗尽仍有阻断时停止调用，给出证据和可选处置，不自动通过。

先执行或复用适用的确定性检查，再审查；获准修复后重验受影响行为。完整交付按 [验证规程](verification.md) 汇总，必需审查用 [审查记录](review-receipts.md) 导入。来源格式未适配时仍可按 [证据保存](evidence-retention.md) 保留真实报告，但不视为已通过机器证据校验。报告范围、输入、审查者、检查、发现处置与未决项，分别给出检查和审查结论。

## 报告组织

独立报告在 findings 下分别组织缺陷、风险、非阻断建议、已接受限制、未解决事项与对下一步的影响。每项发现可复用模板中的六要素块，注明局部编号、严重性和条件；非阻断建议也可使用有序列表，不为填模板编造事实。无发现时删除示例块并写明无，不凑数量。

主审裁决在 inputs 保存来源报告及实际审查者信息表，checks 保存裁决办法与总判定；findings 按采用、部分采用、延期、不采用组织，并保留未决项和下一步影响。每项处置链接来源报告及局部编号，说明依据；部分采用说明接受与未接受的范围，延期说明条件，不能把未解决包装成采用。某类无处置时删除示例行并写明无。

保持五个固定二级章节，主题分组放在三级及以下；按内容需要使用多个表格、段落、列表、强调、代码和分隔线。裁决表可按主题分组或增加所需列，长说明放在邻接段落，不为填表省略判断依据、限定条件或不确定性。格式通过不能代替内容完整性检查。
