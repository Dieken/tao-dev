# 独立判断与对抗式审查

在需求取舍、重要设计、正式评审及范围反复扩张时读取本规程。目标是发现错误前提、遗漏和不必要的复杂度，帮助作出决定；不是证明作者或用户错误，也不是凑够问题数量。

## 一、对用户方案保持独立判断

区分用户要达到的结果、已明确的约束与其提出的实现建议。对会增加组件、状态、依赖、配置或持续工作的建议，先说明收益、必要条件、维护成本和更简单的替代方案，给出采用、缩小、延期或不采用的建议及理由。低影响的明确要求直接处理，不为展示“独立思考”逐项争辩。

用“不增加机制”的方案作比较基线，主动检查能否通过删除、合并、复用或缩小承诺达到目标。已经投入时间、已经写进计划、用户表达偏好或另一模型赞同，都不能单独成为继续投入的依据。若事实和约束不变，不应只因用户从赞成变成反对，就翻转技术判断；用户新增的真实需求、风险偏好与明确约束则应纳入重新权衡。

建议与决定分开记录。对明确的用户决定，说明有根据的重要代价后在授权范围内执行；不能以独立判断为由暗改目标、反复要求确认，或把不同意见自动升级为阻断。出现新证据或违反硬性约束时再提出问题。审查者建议增加的流程和机制也承担同样的举证责任。

## 二、按后果选择审查强度

审查覆盖需求、设计、计划、代码、测试、配置、模板、prompt、用户及运维说明和发布产物。按改动的含义与后果选强度，不按文件后缀判断；例如权限配置和迁移说明中的一行修改也可能需要加强审查。

| 情形 | 默认做法 |
|---|---|
| 局部、低影响且容易撤销 | 作者自查相关差异，执行相称检查；不自动启动跨模型审查 |
| 普通功能或跨模块修改 | 在可用且已授权的预算内，采用独立上下文的审查者；关注需求符合性与实现质量 |
| 数据完整性、权限边界、难恢复迁移、破坏性公共契约、新增持久服务，或关键争议持续未决 | 加强独立审查，优先选择不同模型供应商；明确挑战核心假设和复杂度必要性 |
| 项目或用户明确要求某种审查 | 按既定要求执行，不能用较低级别结果冒充满足 |

跨模型优先考虑与作者不同的模型系列；加强审查优先跨供应商，例如 Anthropic 与 OpenAI，在项目允许的数据、工具和费用范围内使用。不固定易过时的模型名称，也不自动为审查新增供应商或全局安装。

记录实际模型标识、供应商和调用方式；CLI 名称、代理角色名、不同会话或更换提示词都不能证明更换了模型或供应商。信息不可确认时标记未知。同模型的新上下文、另一位人工审查者可以提供有价值的复查，但要如实记录独立程度。跨供应商不可用时优先采用可用的人工或不同模型复核并说明缺口；只有被明确要求的审查条件未满足才构成相应流程阻断，不能默认把所有项目变成双供应商项目。

## 三、先独立检查，再对照作者理由

1. **固定受检版本和输入。** 给审查者原始目标、适用约束与已作决定、当前产物、相关上下文、差异及实际验证证据。代码审查包含受影响调用方和测试，文档审查包含相关实现及引用。记录可核实的输入引用，优先采用固定 VCS 版本；只给作者总结或几行 diff 不足以判断完整行为。
2. **形成独立初判。** 首轮不额外提供作者的自评结论、其他审查者的结论或劝说性摘要；产物内的设计决定和影响判断的事实、授权与约束仍完整提供。审查者先写出关键假设、可能失败的具体场景及待查证点，再阅读作者的自评与补充论证，比较差异。只有能否定的假设才值得继续调查，不以语气强硬充当证据。
3. **主动寻找反例与减法方案。** 检查正常之外的边界、失败、恢复路径，以及需求、代码、测试和说明是否相互矛盾。问清“如果去掉这层机制，哪个真实要求不能满足”；反过来也检查所谓简单方案是否漏掉已承诺的保证。好的产物允许无发现，不强制提出缺陷或替代架构。
4. **把意见转为可裁决的问题。** 每项发现包含定位（文件／行或条目 ID）、相关约束、触发场景、证据或明确的假设、后果与最小解除条件。区分已确认缺陷、待验证风险和非阻断建议；未证实的严重后果不能写成已经发生的事实。
5. **按证据处理分歧。** 优先用需求依据、权威资料、最小复现、测试或基准比较。作者逐项给出采用、不采用、延期或未解决及理由；修改后验证受影响行为。不能根据多数票、模型品牌、置信语气或互相说服后的共识决定通过。

独立审查默认只读产物，实验写入隔离目录，不让审查者边修改受检文件边给原版本盖章。修改后旧发现和证据须确认仍适用。必要的复核只检查改动及其影响范围，不重新开启已解决且无新证据的问题。

## 四、记录与停止条件

复用当前变更的评审或证据位置；需要单独报告时放在其附件中，不另建一套需求与任务。报告至少包含受检输入引用（按 [保存规则](document-layout.md) 优先采用固定 VCS 版本）、范围、审查者及实际模型／供应商、工具执行情况、发现与处置、未决项和剩余限制。人工身份或供应商信息只记录项目需要的程度；未经执行的跨模型审查不能以计划代替记录。

默认一次独立初审，修正后最多一次定向复核；项目已有时间、费用或轮次预算时优先遵循。扩大审查需有新证据、明确增加的范围或新的预算决定，不因“再审可能发现问题”持续扩张。预算耗尽仍有阻断时提交证据与可选处置，由有权决定的人裁决；不能自动通过或重复调用直到某个模型赞同。

判断审查是否值得继续投入，看其发现的可复现缺陷、被证实的错误假设、减少的维护负担、误报和实际成本，不看评论数量或一致率。必要时比较同一任务在单次审查与跨模型审查下的结果。自动调度和统计工具尚未提供时如实记录，不能虚构度量。
