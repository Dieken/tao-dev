# 流程操作与工具调用

在进入需求、计划、实现、调试、恢复、验证或收尾工作时读取本规程。工程判断遵循同包的 [工程规程](engineering.md)；按项目现有语言、目录、工具和已作决定执行。创建或修改 tao 管理文档前读取 [文档规程](documents.md)，使用 skill 提供的格式与模板；CLI 负责实现相同规则。用户通常只表达意图，agent 负责调用与必要参数，不要求用户逐次选择检查类型、范围或级别。

## 先判断可用能力

[工具规程](tools.md) 说明受信任入口、已实现操作和一次性的项目配置。通过本 skill 的 `scripts/tao.py` 或项目明确指定的同一入口调用 `doctor --format json`，按返回的 capabilities 执行；不要寻找或安装 PATH 中碰巧同名的程序。

首次使用或 doctor 报告环境缺失时，读取 [运行环境规程](runtime.md)。在已有依赖准备授权内调用 setup；仅出版目标需要 --publication。用户只提供工作目标，agent 选择必要依赖；普通命令和 hook 不联网安装，未获安装授权时只说明缺口。

当前核心文档命令与配置驱动的行为检查、证据复用可用；接入或执行项目检查时读取 [验证与度量规程](verification.md)。其他操作按真实能力推进。下表包含目标接入点：缺少的操作继续采用项目已有工具，并报告未覆盖条件，不将手工查看冒充自动检查。`tao` 是脚本入口的简写，不要求全局安装。

## 按任务阶段执行

常用操作名为 new、verify、status、handoff；以客户端实际支持的 skill 或斜杠入口调用，不假设两端语法相同。需要创建计划时由 agent 从已知目标提炼 slug；需要交接时先整理简明摘要，再交给工具保存，用户无需准备中间文件。new 不启动实现，handoff 不停止会话、创建回滚快照或移交执行权。

### new：用户给目标，agent 组织草稿

面向开发者的 new 操作接受自然语言描述及会话上下文，不要求 slug。没有额外描述时复用已明确目标；确实无法确定目标才询问。客户端包装传递完整描述，不把它当作 shell 参数或直接拼接成命令。

先理解目标、读取相关材料并判断是否需要新计划；需要时提炼 slug，通过受信任的底层入口调用 `tao new --slug <slug>`。这是 agent 使用的确定性生成操作：显式 slug 是必需值，CLI 不调用模型，不接收自然语言位置参数；缺参应报错且不落盘。直接调用 CLI 的开发者需自行继续填写。

CLI 只创建有结构、元数据及分配标识符的模板骨架，返回路径与 ID；agent 随后填写目标、范围、依据、可确定的验收和下一步，检查格式及内容。未决信息如实记录；不留下模板占位符后就宣称完成，不凭空补齐设计。只生成骨架不能算完成用户的 new 请求，中断时说明未完成，恢复时继续原文件与 ID。

草稿不等于评审通过或完整规划完成。new 本身不授权编码；用户同一请求已授权继续设计或实现时，按已授权范围推进，不强制再输入一个命令。工具不可用时，按同包文档契约直接编写，使用实际可用的安全随机工具分配 ID，不假装调用了 CLI。

### 阶段与动作

流程名称采用 specify、plan、implement、review、verify。澄清属于需求工作，设计与任务拆分属于规划；这些是帮助理解的操作名称，不是每次都要启动的五个命令，也不要求分别生成文件。

| 时机 | 实际动作与最小产物 | 工具接入点，能力存在后才调用 |
|---|---|---|
| 首次进入项目或工具／配置变化 | 确定根目录、已有约定、当前目标及检查能力 | `tao doctor`；配置和能力未变时不反复检测 |
| specify：整理需求 | 复用已知目标与场景，独立分析用户建议，明确范围与验收；已有计划可继续使用 | 需要新计划时 `tao new --slug <slug>`；语言取项目约定，不重复追问；新增正式条目由生成器或 `tao id new` 分配 ID |
| plan：设计与拆分任务 | 检查实现与调用方，比较最小方案，明确依赖、修改范围和验证办法 | 文档修改后 `tao verify --only docs`；查定义用 `tao show <ID>`；工具不替 agent 完成设计 |
| implement：实现或重构 | 完成一个可验证结果，保护不相关工作，同步受影响规格与说明 | 文档变化用 docs 子集，行为变化用 `tao verify --only code` 或项目原生检查；读取局部结果，不声称整个变更完成 |
| 调试 | 保存现场、提出可证伪假设，以最小实验区分原因；修复后重跑原场景与回归 | 用已配置的 code 子集或项目命令执行；不以反复重跑至偶然成功掩盖失败 |
| review：审查 | 读取 [审查规程](review.md)，按风险对相关产物独立审查，加强审查优先跨供应商 | `tao review <CHG-ID>` 取得输入绑定；独立审查后按审查记录规程用 --from 导入实际结果，status 查时效；不虚构自动审查或跨模型执行结果 |
| 恢复会话 | 核实当前目标、决定、阻碍、文件状态与证据，不仅信任交接摘要 | `tao status` 与必要的 `tao show`；绑定已明确的目标，不重新让用户选择 |
| 中断或交接前 | 保存目标、约束、决定、实际状态、证据入口、阻碍和下一步 | 支持时 `tao handoff --from <file>`；否则更新项目既有交接位置，不保存整段会话 |
| verify：交付前 | 核对验收、必需检查、任务与依赖、审查、证据及真实授权，说明结果与限制 | 执行不带 `--only` 的 `tao verify` 并读取完整报告；无单独收尾命令，不自动提交、合入或发布 |
| 删除条目或构建书籍 | 处理引用与退役；实际检查生成链接 | 分别使用支持的 `tao retire`、`tao docs build`，保持写入范围；构建不附带部署 |

ID、日期、章节、任务与证据的精确格式由文档规程和格式注册表维护；不要在流程阶段另造字段或编号。当前模板可由 agent 填写，工具能力存在后才调用生成器。

局部文案／格式修正采用相称检查和交付说明，无需新建变更档案。新建 tao 管理文档使用统一契约；已有文件按需接入，范围外或未支持的格式不能计入校验通过。实际没有必要行为检查时应有明确适用性依据；不能仅因修改的是 Markdown，就跳过 prompt、配置或操作说明可能影响的行为。

## 自动选择，必要时才覆盖

当前变更由显式 ID、变更目录、当前任务绑定或唯一活动变更确定；只有存在实际歧义时才询问。完整 verify 按项目已确定的策略选择文档、代码与证据检查。配置一次后不反复让用户选 profile；发现新风险则明确增加所需检查，不暗中降低门槛。

编辑期间可以用 `--only docs`、`--only code` 或 `--only evidence`，它们只给局部反馈，不替代交付前的完整调用。`--scope changed` 仍包含必要依赖和全局一致性检查；基线或影响不明时扩大到 all。预算不足或必要工具缺失时如实记录，不靠局部模式绕过。

对副作用或检查选择有疑问时用支持的 `--dry-run` 查看计划；它不执行验证，不构成证据。hook 在预算内执行 docs 子集检查；完整验证由 skill 在交付前触发，无需用户再运行额外的收尾命令。重复事件和相同输入的检查应合并，必要的旧证据复用以可核实的输入引用及有效期为依据。

## 读懂结果并保持边界

tao 退出 `0` 表示本次所选检查通过，`1` 表示条件不满足，`2` 表示配置／工具故障、能力缺失或检查未完成。`--only` 的 0 只对应 `coverage: partial` 和 `readiness: not-evaluated`；dry-run 的 0 仅表示计划有效。整体完成依据必须来自完整调用的 `coverage: complete`、`readiness: checks-satisfied`，再结合实际语义审查和授权。工具条件满足不代表语义正确、风险已获批准或已经发布。

项目原生命令按其真实退出码和输出解释，不能套用 tao 的退出码约定。逐项区分通过、失败、未执行、不适用和已过期；复用结果标记 reused 并给出证据入口，不用代码量、任务勾选或模型复述代替证据。

受检输入在验证期间或之后变化时重验受影响部分。优先按 [输入保存规则](evidence-retention.md) 引用固定 VCS 版本及受检范围，另核对影响执行的版本外输入和必要环境；不默认持久保存逐文件哈希。默认在计划 verification 中保存简短结果，原始输出留在 tmp/tao/ 或 CI，不自动纳入 VCS；按保存规则决定是否另存独立摘要或必要报告。日志过期不自动取消历史任务完成状态，也不能据此直接复用为当前结果。

CLI、斜杠命令和 hook 只报告实际支持与执行的能力。测试本 skill 时仅在隔离项目或单次调用内启用，不全局安装、不修改全局配置；必要能力缺失时报告限制，不能伪装整体通过。
