# 流程操作与工具调用

按任务阶段选择动作，工程判断遵循 [工程规程](engineering.md)。用户表达目标，agent 复用项目约定并选择工具、参数和检查范围。

## 按需判断 tao 能力

- **局部代码、测试或配置修改**：既无 tao 文档同步职责也未绑定 tao 变更时，直接使用项目原生工具；不读取工具、运行环境或验证规程，不运行 doctor。
- **调用 tao 操作、管理 tao 文档或使用配置化检查与证据**：读取 [工具规程](tools.md)，通过 skill 的 `scripts/tao.py` 或项目明确指定的同一入口运行 `doctor --format json`，按 capabilities 执行。配置和能力未变时不反复检测；不从 PATH 猜测同名程序。
- **首次准备或环境缺失**：读取 [运行环境规程](runtime.md)，在已有安装授权内调用一次 setup 准备核心与出版环境。普通命令和 hook 不隐式安装。
- **配置、执行项目检查或解释证据复用**：读取 [验证规程](verification.md)。只运行项目原生命令不触发该引用。

下文 `tao` 是脚本入口的简写。能力不可用时使用项目已有工具或同包模板继续可完成的部分，明确缺口，不将手工查看冒充自动检查。

## new：从目标得到可用草稿

1. 复用用户描述和会话中的目标；确有歧义才询问。读取相关材料，判断是否需要新计划。自然语言作为上下文处理，不直接拼接 shell 参数。
2. 需要新计划时读取 [文档规程](documents.md) 及对应模板，由 agent 提炼 slug，调用 `tao new --slug <slug>`。CLI 只生成骨架并返回路径与 ID；参数和副作用见工具规程。
3. 填写目标、范围、依据、可确定的验收和下一步，消除占位符并检查内容与格式。未决信息如实记录；中断后继续原文件和 ID。仅生成骨架不算完成 new。
4. 草稿不等于评审通过或完整规划完成。new 本身不授权编码；用户已授权继续设计或实现时按该范围推进，无需另一个命令或重复批准。

工具不可用时按同包契约直接编写，用实际可用的安全随机工具分配 ID。直接调用底层 CLI 的开发者也需要继续填写骨架。

## 阶段与动作

specify、plan、implement、review、verify 是阶段名称，不要求逐一调用命令或各建一份文件。表中 tao 接入点仅适用于需要 tao 的任务。

| 时机 | 实际动作 | 工具接入点 |
|---|---|---|
| specify：整理需求 | 明确目标、范围与验收；独立分析实现建议 | 按上述 new 流程创建必要草稿；新增 ID 用生成器或 `tao id new` |
| plan：设计与拆分任务 | 比较最小方案，明确依赖、修改范围和验证办法 | `tao show <ID>` 查定义，文档修改后 `tao verify --only docs` |
| implement：实现或重构 | 完成可验证的小增量，同步受影响说明 | 文档用 docs 子集，行为用 `tao verify --only code` 或原生检查 |
| 调试 | 保存现场、提出可证伪假设，以最小实验区分原因 | 修复后重跑原场景与相关回归 |
| review：审查 | 读取 [审查规程](review.md)，按风险独立检查相关产物 | `tao review <CHG-ID>` 取得绑定，按 [记录规程](review-receipts.md) 导入实际结果 |
| 恢复会话 | 核实目标、决定、阻碍、文件状态与证据 | `tao status` 与必要的 `tao show`；不只信任交接摘要 |
| 中断或交接 | 写明目标、约束、决定、实际状态、证据入口、阻碍和下一步 | agent 整理摘要后 `tao handoff --from <file>`；不可用时更新项目既有交接位置 |
| verify：交付前 | 核对验收、检查、任务、审查与真实授权 | 按下节执行并解释结果 |
| 退役或构建书籍 | 处理引用、保留退役记录，实际检查生成链接 | `tao retire`、`tao docs build`；精确规则见文档与出版规程 |

创建、修改或审查 tao 管理文档时读取文档规程，按本次修改逐步接入。局部文案或格式调整无需新建变更档案；检查强度取决于实际影响，prompt、配置和操作说明不能仅因后缀是 Markdown 就免于行为验证。

客户端以实际支持的 skill 或斜杠入口执行 new、verify、status、handoff，不假定两端语法相同。handoff 保存摘要，不停止会话、创建回滚快照或移交执行权；构建不附带部署。

## 验证与收尾

1. **确定目标和范围。** 根据显式 ID、所在变更目录、当前任务绑定或唯一活动变更确定目标；CLI 无法唯一选择时由 agent 传入 CHG ID，只有上下文也存在歧义才询问用户。按既定策略选择检查，新风险需要补充检查时说明依据。
2. **编辑期间取得局部反馈。** 使用 `--only docs|code|evidence` 或项目原生命令；hook 也只提供 docs 子集反馈。`--scope changed` 包含必要依赖和全局一致性检查，基线或影响不明时扩大到 all。`--dry-run` 仅预览选择，不执行检查。
3. **交付前核实完整条件。** 已绑定 tao 变更且已配置完整检查策略时，执行不带 `--only` 的 `tao verify`，按验证规程检查覆盖、就绪条件及必需审查。未接入 tao 文档或完整策略时，执行项目已有的相称检查并说明 tao 就绪状态未评估。预算不足、必要工具缺失或阻断未解时，不用局部结果代替完成；无需额外的收尾命令。
4. **解释实际结果。** tao 退出 0 表示所选操作成功，1 表示条件不满足，2 表示配置／工具故障、能力缺失或未完成；局部模式和 dry-run 的成功均不代表交付完成。原生命令按自身退出码和输出解释，分别报告通过、失败、未执行、不适用和过期；复用结果标记 reused 并给出入口。工具条件满足仍需语义审查与真实授权，不自动提交、合入或发布。
5. **保存可复核结论。** 输入变化后重验受影响部分；默认在计划 verification 保存简短结果，原始输出放临时目录或 CI。需要选择输入引用、保存期限或独立报告时读取 [证据保存规则](evidence-retention.md)。历史结果与当前复用资格分别判断。
