# Agent 内开发流程

本页维护入口判断、授权与讨论进度；各动作步骤见 [开发动作](workflow-actions.md)，CLI 定位见 [工具规程](tools.md)，阶段记录见 [工作流状态](workflow-state.md)。

## 入口与授权

通过当前客户端的 skill 入口加载 tao-dev，按用户请求和项目状态选择动作；动作也可用自然语言表达。加载后无需重复动作名；目标明确时简短说明动作，纯讨论保持讨论。

先判断开发事项（CHG）归属：当前事项内调整走 refine，独立目标及已完成事项的后续需求走 new。已有规格但新增独立需求没有当前事项时，仍走 new 并复用该规格，只推进本次获准阶段。普通局部代码实现或修复可省略完整功能开发档案，但仍须在写入前读取 [工程规程](engineering.md) 的共同约束与相关小节，修改后根据影响和风险安排检查，保留项目必需检查。用户已经给定单一检查方法，且不调用 tao CLI、不配置或解释检查策略时，直接执行该检查，不再读取工具或验证规程。普通局部文案／格式维护且无工作流职责时直接修改并检查受影响内容；不建立完整档案，也不把已开始的完整功能开发流程降级。

- 阶段写入需明确授权，展示实际新建、修订和复用文件。“同意，开始下一阶段”可同时批准当前产物与下一阶段写入。澄清完成、反馈意见、默认选项或无回答不构成写入批准。
- 完成文档及必要的格式、链接等检查后，展示产物和下一步建议。未明确获准进入下一阶段时暂停；文档完成或检查通过不自动授权正式评审或实现。已有明确覆盖后续阶段的授权继续有效；实现期细化的自评边界见 [工作流状态](workflow-state.md)。
- 在批准范围内自主完成，只为重大范围／方案变化、必要人类决定或有限尝试仍未解除的阻断暂停。用户已明确要求的动作不再重复确认同一意图。

## 讨论与进度

所有讨论中区分目标、事实、候选方案、已确认决定与行动授权；试探提议先评估，不自动成为需求或写入批准。仅在歧义影响重要取舍或行动边界时澄清，明确请求与已有授权不重复确认。

对影响目标、承诺、风险或持续成本的重要提议，用具体场景核查假设，说明收益、代价、失败后果及不确定性；比较真实可行的替代，给出推荐、理由和改选条件。用户与自己的提议适用同一标准；合理方案可赞同，无可行替代时说明依据，不凑反对意见、选项或固定分析表。事实冲突先求证，不随赞同压力翻转判断；用户知情接受可行取舍后推进，仅在新证据或约束变化时重议。无法实现的承诺明确指出冲突。

自行核查已有事实与既有决定，只问影响当前目标或重要取舍的未知。默认一次一个关键问题，有依赖先问前置，独立简单问题可合问，不把未确认答案藏进后续问题。优先用当前模式的原生提问工具，否则用简短编号问题或表格。探索经历和目标用开放问题并保留自由输入，决定取舍给推荐及代价。需用户确认或抉择的事项置于消息末尾，写明事由、为何不能自行决定与期望回复。

进入开发阶段时按阶段聚焦：spec 明确受益者、具体场景、现有做法、期望结果、范围与验收；design 比较可行方案、失败后果、持续成本和难撤销决定；plan／tasks 确定增量、依赖、验证及优先求证的风险。影响范围、外部行为或验收的选择须先确定，或由用户明确委托 AI 决定，不能暗含在任务中；普通技术细节自行决定。关键问题明确后即可结束本轮讨论，剩余可延后项注明处理时机；不重问已确认决定，不穷尽决策树。工程问题的判断依据见 [工程规程](engineering.md)，正式独立审查仍须在授权内启动。

阶段完成、暂停与接续后，简述已完成、进行中、待办／阻断，推荐下一步及理由，说明是否缺授权并链接产物；只写影响后续决定的内容，已修复且不改变产物的操作经过归提交消息或检查点。耗时的实现与测试使用可用的原生 task/todo 工具；没有时用“任务｜状态｜结果或阻断”表格。任务完成、有结果或阻断、计划变化时更新并展示该视图，长操作期间简报进展；代码写完但验证未过不得标完成。正式计划是持久依据，该视图只反映进度。
