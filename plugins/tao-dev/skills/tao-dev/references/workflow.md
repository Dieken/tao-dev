# Agent 内开发流程

本页维护用户动作、阶段与授权；CLI 定位见 [工具入口](tools.md)，阶段记录见 [工作流状态](workflow-state.md)。

## 入口与授权

通过当前客户端的 skill 入口加载 tao-dev，按用户请求和项目状态选择动作；动作也可用自然语言表达。加载后无需重复动作名；目标明确时简短说明动作，纯讨论保持讨论。

先判断事项归属：当前事项内调整走 refine，独立目标及已完成事项的后续需求走 new。已有规格但新增独立需求没有当前事项时，仍走 new 并复用该规格，只推进本次获准阶段。普通局部代码实现或修复可省略完整 feature 档案，但仍须在写入前读取 [工程规程](engineering.md)，修改后执行相称检查。用户已经给定单一检查方法，且不调用 tao CLI、不配置或解释检查策略时，直接执行该检查，不再读取工具或验证规程。普通局部文案／格式维护且无工作流职责时直接修改适用文件、执行相称检查；不建立完整档案，也不把已开始的完整 feature 流程降级。

- 先查项目与既有决定，只询问影响目标、授权或重要取舍的未知。优先使用客户端原生提问工具，推荐项说明理由并保留自由输入；不可用时给简短编号选项。
- 阶段写入需明确授权，展示实际新建、修订和复用文件。已有覆盖后续工作的授权持续有效；“同意，开始下一阶段”可同时批准当前产物与下一阶段写入。澄清完成、反馈意见、默认选项或无回答不构成写入批准。
- 在批准范围内自主完成，只为重大范围／方案变化、必要人类决定或有限尝试仍未解除的阻断暂停。用户已明确要求的动作不再重复确认同一意图。
- 有 task/todo 工具时映射实际阶段与任务，持久进度以文档为准。阶段结束报告完成、待做、阻断与下一步，链接实际产物。

## setup：项目接入

按 [项目接入](project-setup.md) 探测工具、配置最小检查策略并执行获准基线。需要 tao 能力但缺配置时，可在已有写入授权内补齐，不要求先重装插件。

## new：需求到规格

1. 调查现有行为、规格与相似实现，澄清业务范围、场景和验收；路径、术语和文档语言按项目约定处理。
2. 汇总需求与未决点，确认澄清完成和开始工作副本／spec 的授权。意见未收敛时继续讨论。
3. 调用 workflow start，默认使用隔离 worktree；复用已有副本，记录根、分支与基准。前提和冲突处理见状态接口。
4. 在副本中编写或修订 spec，保存检查点、执行文档检查并展示链接，停在 spec 检查点。

正式文档采用 [文档规程](documents.md)。完整 feature 的 spec、design、plan 各有入口，优先复用；位置与拆分见 [文档组织](document-layout.md)。仅在编写 plan 时调用 `tao new --slug <原 slug> --change <CHG-ID>`，不提前生成空计划或未来阶段产物。

## continue：推进或恢复

按 [状态接口的接续步骤](workflow-state.md) 核对实际副本、文档、批准、进度和运行中操作，再在已有授权内继续。缺授权时展示下一阶段范围；文档阶段完成后停在用户检查点，意见在当前阶段修订。

| 阶段 | 工作 | 下一步 |
|---|---|---|
| spec | 业务范围、REQ／UC、可判定验收 | 查看／修改，或批准 design |
| design | 最小方案、接口、约束、失败与验证设计 | 查看／修改，或批准 plan |
| plan | 可验证 TASK、依赖、修改范围和检查办法 | 修改、文档审查或批准实现 |
| implement | 按批准任务实现与验证，更新进度 | review |
| review | 确定性检查与实际审查 | 修订／修复或 finish |
| finish | 按授权整理、集成与清理 | 报告实际结果 |

进入实现前，若当前版本尚未完成文档审查，提供先审查或跳过可选审查的选择，记录真实决定；项目必需审查不可跳过，已完成的审查不重复询问。

## refine：修订已有内容

定位受影响的 spec、design、plan 及下游工作；按授权更新。业务范围变化同步规格、设计与任务，技术方案变化同步设计与计划，纯任务拆分只改安排。用 workflow revise 撤销相应下游批准，保留代码和稳定 ID。正式删除走 [退役流程](retirement.md)。展示差异与检查点，修订本身不自动授权实现。

## implement：完成批准计划

显式 implement 在计划明确且前置条件满足时即授权该计划的实现与测试；前置文档阶段或审查选择未完成时回到对应检查点。按依赖完成小增量、相称检查和修复，依据真实结果勾选任务并保存检查点；测试与工程取舍见 [工程规程](engineering.md)，结果保存见 [证据规程](evidence-retention.md)。提交遵循项目与用户授权。

## review：审查与验证

按 [审查规程](review.md) 确定范围、方式与预算，使用 [调度接口](review-runs.md) 固定输入和记录轮次。文档阶段审查文档，实现后对照有效文档审查代码与测试。检查、发现和处置分别报告，通过后进入 finish。

## 其他动作

- **debug**：先调查与复现，再按工程规程定位原因。定位请求不授权补丁；已有实现授权覆盖时直接调试、修复和回归，业务承诺变化转 refine。
- **status**：只读展示阶段、任务、批准和证据时效及下一步，不运行验证或自动恢复；事项仍不明确时请用户选择。
- **handoff**：按 [状态接口](workflow-state.md) 和 handoff 模板保存恢复摘要，给出文件链接、worktree／branch 与可粘贴的 continue 输入。
- **docs**：显式调用授权常规本地构建输出，按 [出版规程](publication.md) 构建并检查 HTML。缺书入口时展示拟建导航并确认，构建不含部署。
- **finish**：核对交付检查、审查、运行中操作与未提交文件；按已确认对象执行保留、合入、推送和 worktree／分支清理。只删除本事项拥有且已确认可删的内容，不强制丢弃未保存工作。按工程规程沉淀有用知识，报告完成和未完成事项。
