# 证据与产物保存

保存检查结论、报告或受检输入引用时读取。本文维护保存原则；机器复用条件见 [验证规程](verification.md)，文档字段见 [文档规程](documents.md)。

## 位置与保留

| 内容 | 默认位置与处理 |
|---|---|
| 普通验证结论 | 计划 verification，随计划保留 |
| 独立摘要 | 需要跨开发事项引用、报告较长或周期不同时用 `<plan-stem>/evidence/`；无开发事项用 docs/evidence/ |
| 正式审查报告与裁决 | 按 [报告写法](review-reports.md) 保存为受管理 evidence，位置与命名由该页维护 |
| 原始输出、日志、覆盖率、截图和临时输入清单 | tmp/tao/ 或 CI 产物，不纳入 VCS，按既定期限清理 |
| 本地书籍 | temporary 下 book/ |
| 可重建索引与短期锁 | temporary 下 cache/ |

配置的 temporary 映射整个生成根，仅在实际写入时建目录；`.tao/` 保存控制信息，不存生成报告。只清理本事项归属明确且未被活跃操作使用的产物，不清空共享 tmp，也不删除仍要求保留的唯一材料。正式退役记录按 [退役规程](retirement.md) 管理。

结论至少记录受检版本与范围、执行时间、命令及必要环境、实际结果和未验证范围。已有 CI 结果引用运行标识与链接，计划保留简短结论。原始输出未长期保存时明说；不能因引用了临时路径就视为持久材料。

对话反馈和临时分析可直接返回；临时原始输出存 temporary 或 CI 产物，不因被讨论或裁决就自动转成正式文档。已决定持久化为受管理交付文档的报告按 [报告写法](review-reports.md) 整理，不能通过换目录绕过 schema。工具不可用时交付已完成的分析并标明格式校验、ID 或正式保存缺口；必需正式记录仍待补齐，不伪造完成。

性能比较、事故调查、发布或审计确需日后复查原数据时，保留必要报告到持久产物库，或把选定小文件纳入 VCS，记录位置、必要校验和及期限。保留已有正式 EVD 标识，不为合并短摘要随意删除正式对象；无需为常规日志新增归档服务。

## 输入引用

计划在 verification 记录；独立 evidence 使用 inputs.fingerprint。该字段是输入引用，不限定为哈希，不要求逐文件清单：

| 受检状态 | 最小记录 |
|---|---|
| VCS 可还原全部输入 | 仓库标识、完整固定修订号、检查范围与排除项、受检内容相对该版本无差异的核对结论 |
| 有未提交或版本外输入 | 基线版本、已有持久差异／快照及其范围；无可还原材料时标明不可还原，不复用为当前通过证据 |
| 无 VCS | 已有持久快照或归档及必要校验和，不默认另建快照系统 |

检查版本是否覆盖暂存／未暂存修改、相关未跟踪文件、执行所需的被忽略配置、数据与依赖。环境和依赖版本另记；不能以干净工作区或会移动的分支、标签、HEAD 代替上述核对。内容哈希用于检测变化，不能恢复内容。

不为记录版本擅自提交用户代码；未提交修改也可产生实测结果，但须说明还原能力。证据提交可晚于受检提交。仅新增报告不要求重跑全部检查；受检范围排除明确声明的本轮输出和缓存，但包含历史报告及实际影响行为的输入。

## 字段、结果与时间

独立 evidence 的 inputs.fingerprint 填受检输入引用，environment 填环境，checks 填命令／观察、预期、结果与报告入口，findings 填限制，retention 填保存安排。reports 可明确写原始输出未长期保存及原因。

frontmatter 的 result 表示报告所述受检对象在声明范围内的总体结论，不能用脚本执行状态替代；coverage 独立表示覆盖范围。结果枚举适用于全部 evidence，包括审查报告：

| result | 含义 |
|---|---|
| passed | 有依据确认声明范围内满足检查或审查标准；不扩大 coverage |
| failed | 有依据确认未满足标准；审查的 changes-requested 对应此值，正文保留原结论措辞 |
| not_run | 本报告所述检查或审查确实未执行 |
| not_applicable | 所述检查或审查不适用，正文说明依据 |
| stale | 本报告明确判定证据不再适用于其声明的受检输入，正文记录原因；不因日志到期改写历史结果 |
| unknown | 原材料未记载总体结论，或依据不足以确定；正文保留已有发现、检查结果与未知原因 |

审查模板的 result、coverage 是占位符，据实选定后才通过校验。审查已执行但未形成总体结论时不能填 not_run，也不能由缺陷数量、无阻断描述或命令通过推断 passed／failed。unknown 不代表通过、不适用或已完成验收。

recorded_at 记录实际形成本记录的时刻，不冒充审查执行时间；编辑既有记录时保留原记录时刻。审查／检查执行时间及其来源另写在正文，无法确认则写未知，不能根据文件修改时间、目录日期或记录时刻猜测。

## 历史结果与当前复用

分别判断历史执行结果、原始材料可用性和当前适用性。日志到期不改写历史结果或任务完成状态。缺必需材料或无法确认输入一致时不复用，输入变化按影响重验，原始材料缺失如实标明；复用资格、时限与 require_logs 见 [验证规程](verification.md)。
