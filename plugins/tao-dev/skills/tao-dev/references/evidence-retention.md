# 证据与产物保存

决定验证结论、原始报告、临时产物或受检输入引用的保存位置和期限时读取本文。文档类型与字段见 [文档规程](documents.md)，证据复用的判定规则见 [验证规程](verification.md)。

## 保存位置

```text
docs/plans/<yyyy-mm>/
  <yyyymmdd>-<slug>.md              # 计划与默认验证结论
  <yyyymmdd>-<slug>/evidence/       # 按需：独立摘要或须保留的报告
tmp/tao/                           # 可映射的生成根，默认不纳入 VCS
  cache/                           # 可重建索引、缓存及短期锁
  <run-id>/                        # 本次日志、测试、覆盖率、诊断或基准报告
  book/                            # 本地出版产物
```

默认生成根为项目内的 `tmp/tao/`，仅在实际生成文件时创建；已有生成目录可通过项目配置映射，不要求另增顶层目录。下属 cache/、各次执行目录及 book/ 一起随生成根映射；.tao/ 不存放生成产物。清理仅限已确认的 tao 生成目录，不清空整个 tmp/ 或共享生成根，也不删除活跃操作所用的文件。

文件名是示意，不要求工具统一生成这些格式；只保存实际产生的文件。`tmp/tao/` 默认通过项目所用 VCS 的忽略机制排除，不能因引用了路径就变成持久证据。CI 临时产物可过期，本地报告可以清理，不应作为长期完成声明的唯一依据。

退役目录按首次实际退役按需建立，JSONL 格式与生命周期见 [文档规程](documents.md)。按日期分文件不保证没有多人冲突，也不改变 ID 的全局唯一性约束；已有配置可映射文档根，但不能把退役记录归为工具缓存。清理缓存和锁前确认没有活跃的写入操作，丢失缓存后应能从源文档与退役记录重建索引。

## 默认留结论，按需留原始报告

普通变更把验证结论写在计划的 verification 章节，随计划保留，不另建 evidence/ 或 EVD 文档。最小记录包括受检版本与范围、执行时间、命令与必要环境、实际结果及未验证范围；原始输出未长期保存时明说。已有 CI 检查结果可引用其运行标识和链接，同时在计划中保留简短结论，不复制整份输出。

stdout、详细测试结果、覆盖率、诊断日志、截图和临时输入清单默认位于 tmp/tao/ 或 CI 产物区，不纳入 VCS，按既定期限清理。持久保存的输入引用与简短结果不因原始输出过期而删除。没有 CI 或持久产物库时仍采用同一规则，不为归档常规日志新增服务。

需要跨变更独立引用、报告较长或保存周期不同，才使用独立 evidence 文档。性能比较、事故调查、发布验收或明确审计要求需要日后检查原始数据时，保存必要报告到持久产物库，或将选定的小型文件纳入 VCS；记录位置、必要校验和及期限。不要用忽略整个 evidence/ 的办法隐藏应保留的摘要，也不保存凭据。已有独立标识符的摘要可精简保留，不为合并小文件随意删除正式对象。

历史执行结果、原始材料可用性、对当前输入的适用性分别判断。日志未保存或过期，只说明原始输出不可读取，不自动将历史 passed 改为 failed、不自动取消任务完成状态。复用到当前交付时，检查持久摘要是否足以支持结论、输入与环境是否匹配，以及项目是否要求原始报告；缺少必需材料才阻断该项复用。摘要过于笼统或来源不可核实时不能只凭一句“通过”放行；输入变化仍按范围重验。

## 受检输入：优先引用版本，不复制文件清单

默认在计划的 verification 章节记录输入引用；独立 evidence 文档使用 inputs 章节的 fingerprint 字段。不新建只有版本号的文件，也不要求 inputs.sha256 或逐文件哈希清单。该字段表示可核实的输入标识，不限定为哈希；FINGERPRINT 模板变量按下面的规则填写。

| 受检状态 | 最小持久记录 |
|---|---|
| 受检内容可由 VCS 版本完整还原 | 仓库标识（本仓库可写“本仓库”）、完整不可变修订号、检查范围与排除项、受检范围相对该版本无差异的核对结论 |
| 存在影响检查的未提交或版本外输入 | 基线版本及已有持久差异／快照的引用，补充其覆盖范围；没有可还原记录时明确标记输入不可还原，不能复用为当前通过证据 |
| 未使用 VCS | 已有持久输入快照或归档的引用与必要校验和；不默认新造快照系统或全项目清单 |

检查版本是否覆盖实际输入，包括暂存和未暂存修改、相关未跟踪文件、被忽略但参与执行的配置或数据，以及外部依赖。依赖版本和必要环境记在 environment；不能仅凭工作区状态干净就假定版本覆盖了全部输入。不使用会移动的分支名、标签名或 HEAD 字样替代固定修订号。

受检修改已提交时可直接验证该版本，之后单独保存证据；不为了版本引用擅自提交用户代码。验证未提交修改也可以产生当时的实测结果，但要如实记录还原能力。内容哈希可用于检测变化，不能单凭哈希恢复输入；有明确审计或差异定位需求才保存逐文件清单，临时计算清单默认留在 tmp/tao/，不纳入 VCS。

运行前后核对版本、受检范围及影响执行的版本外输入；确认输入变化则标记 stale，无法确认一致性则不可复用，不把相同版本号当作充分条件。证据保存提交可以晚于受检提交；仅新增报告不要求重跑所有检查。排除生成报告、证据自身与缓存，但不能排除实际影响行为的源文件。清理遵循保存期限，不删除仍要求保留的唯一材料；原始输出不可用时如实标注，历史结果与当前复用资格分别处理。
