# tao 术语

涉及 tao 概念、受控命名或用词冲突时查询对应条目。消费项目领域术语由项目 glossary 维护；精确语法见 [文档规程](documents.md)。

## 易混淆概念

| 用语 | tao 约定 |
|---|---|
| 标识符（Identifier） | 对象的固定标识；不用“身份”或“标志”指代 ID |
| 对象同一性（Identity） | 修改前后仍是同一对象；与认证身份区分 |
| 规格／设计／计划 | 分别维护承诺与验收、实现选择与理由、一次事项的执行安排 |
| 条目（Entity） | 可独立引用的需求、用例、决策或任务；普通段落不是条目 |
| 篇／章 | 按读者职责／主题组织阅读，不增加实体类型 |
| 验证／验收 | 检查约束和行为／判断是否满足约定交付；工具检查不自动作出验收决定 |
| 产物／证据 | 文件是产物；绑定输入、条件和结果且可复核的记录才是证据 |
| 开发事项（CHG）／变更 | 一次有独立目标的开发工作；「变更」只表示一般意义的修改，不指该对象 |
| 检查回执 | tao 保存的一次检查执行记录，含输入指纹、结果与日志位置；不是审查结论 |
| 审查者 | 承担独立判断的一个上下文，可以是人也可以是模型；计数不用「人」作量词 |
| schema／profile | 结构与关系契约／具体文档类型采用的字段、章节与条目 |
| 退役／弃用 | 退出有效集合／不建议继续使用；弃用不自动移除定义 |
| 独立／跨模型／跨供应商审查 | 独立判断上下文／实际不同模型／不同模型供应商；角色和 CLI 名不证明来源差异 |
| 对抗式审查 | 用具体反例挑战假设与复杂度，允许无发现 |
| SDD | 本项目指 Spec-Driven Development，规格驱动开发 |

## ID 类型

| 前缀 | 对象 |
|---|---|
| DOC | 文档本身 |
| REQ | 可独立验收的需求 |
| UC | 验收场景或性质，通过 verifies 关联 REQ |
| ADR | 技术决定 |
| TASK | 可验证工作单元，含依赖与证据 |
| CHG | 开发事项，计划之前也可存在；与计划 DOC 不同 |
| EVD | 独立验证记录，与文档 DOC 和报告文件名不同 |

完整格式由注册表定义；文件及其内条目各有独立 ID。只将跨文档易混淆或反复误用的概念提升为项目受控词汇，局部解释留在所属文档。机器字段保持原名，显示标签使用项目语言。
