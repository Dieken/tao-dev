# 工程规程

用于需求、设计、实现、调试与审查中的判断，不要求逐条填表。先满足正确性、数据完整性、安全和明确运行约束，再减少理解、修改、部署与运维成本；验证强度随风险和不确定性调整。

## 共同约束

以可观察的用户结果和验收界定范围；已承诺行为不能改称限制来通过验收。修改前核对相关实现、调用方和已有决定，重要且不确定的判断用资料、反例或最小实验求证。讨论与授权遵循 [流程操作](workflow.md)，普通技术细节在授权内决定。

纠正自身或已有错误时，先找出能检索到的共同特征，确定同类问题和受影响范围，再检查授权范围内所有仍在使用的实现、测试、配置、权威文档，以及生成派生副本的源文件；不能只修本次新增或当前被指出的一处。找到的每一处都要修复，或用可核实的依据说明为什么无关、必须保留或超出授权；派生副本应先修改源文件，再重新生成。超出授权的同类问题应说明位置和影响，并请求扩大范围；未获权前只能报告部分纠正。不可变的历史证据保留原貌，在当前权威入口记录勘误或失效。未说明搜索范围和未处理的结果，不得声称已清理干净。

执行前明确目标与预期；依赖结果继续或声明完成前，回读目标文件、状态或产物，而非仅接受退出码或写入摘要。批量编辑核对全部预期修改及必要保留内容；原子操作失败时先确认整批状态。观察覆盖预期后停止，不递归核验读取命令；结果矛盾时才换直接读法，无法观察则标为未确认。此规则适用于所有工具，核验强度随风险调整。

检查需求与行为，不能削弱断言或靠偶然重跑换通过；未通过必要验证不标完成。低影响文案或格式修改检查受影响内容，不为仪式新增测试。行为变化同步权威文档，结果按实际验证范围报告。

重复发生、现有规则未阻止、检查未发现，或同一模式可能影响别处的错误，均视为可重复失效。纠正结束前，把防复发措施放在最早能自动拦下错误的位置，优先使用类型、数据约束、生成器、校验、回归测试、静态检查或已有 CI；同时覆盖代表性错例和合法反例，确认修复前能失败、修复后能通过。如果确实无法由工具自动检查，更新实际会被读取的权威规程，补充可运行的行为场景，或明确说明仍缺少自动检查。对话反思、道歉、计划／裁决／复盘文字、检查点、提交说明和单点修补都不构成防复发措施。

## 按场景读取

任务涉及下列场景时读取 [工程专题](engineering-practices.md)，按对应小节判断；普通局部修复使用上述共同约束即可。

| 场景 | 专题 |
|---|---|
| 方案设计、抽象或引入依赖 | 复杂度与边界 |
| 状态、并发、失败处理或权限 | 状态、失败与安全 |
| 跨模块实现或并行协作 | 实施与协作 |
| 设计测试、证据复用或度量 | 验证与证据 |
| 调试或正式审查 | 调试与审查 |
| 发布、迁移或性能 | 运行与演进 |
| 收尾或维护长期知识 | 知识维护 |
