# 工程规程

用于需求、设计、实现、调试与审查中的判断，不要求逐条填表。先满足正确性、数据完整性、安全和明确运行约束，再减少理解、修改、部署与运维成本；验证强度随风险和不确定性调整。

## 目标与取舍

需求以可观察的用户结果和验收界定，受益者可包括维护者，优先交付最小完整路径。未来规模、额外渠道和更强保证须有实际依据；已承诺行为不能改称限制来通过验收。修改前核对相关实现、调用方和既有决定；重要且不确定的判断要找出推翻它的条件，用资料、反例或最小实验求证，不强求量化收益才允许探索。

独立判断、备选比较与讨论收敛统一按 [流程操作](workflow.md) 的讨论原则。工程取舍用相关实现、契约、术语定义与具体边界场景核查主张；发现实际行为与用户描述不同，指出差异并区分现状、期望与缺陷，按有效约束求证。新增持续复杂度的机制须比较可行的简单替代，说明当前需求下的收益、失败方式与维护成本；已投入成本不代替必要性依据。重要取舍按文档职责记录理由，不因日常讨论另建档案。

## 复杂度与边界

抽象重复的业务知识或已证实的变化方向，不因表面相似建立扩展点。独立部署、扩缩容或故障隔离的收益足以承担通信与一致性成本时才拆服务。引入依赖评估维护、使用限制、安全和退出成本，并验证兼容行为。

模块隐藏知识并暴露明确契约，减少调用者需要了解的细节。无独立契约价值的薄包装可合并；局部行为频繁跨文件同步时先检查知识归属，不以增加转发层处理边界泄漏。同等正确性和可读性下减少代码与分支，不用压缩语句或机械行数门槛换取表面精简。

## 状态、失败与安全

用领域状态、不变量、类型和边界约束表达正确性，明确数据所有者与写入者；并发和多步操作设计原子性、竞争与恢复。对可能造成严重后果的状态转换，根据风险采用性质测试、推导或形式化论证。

失败区分业务拒绝、暂时故障与不变量破坏，保留调用方所需语义。新增防护、降级、重试或恢复状态前，确认失败路径可达，核对上游、类型与运行时保证，并比较直接报错或人工重试能否满足需求。仅在安全且幂等或可去重时有限重试；检查恢复是否引入重复执行、状态损坏或吞错。数据丢失、重复执行和权限越界等可能造成严重后果的操作路径，在实现前确定防护、检测与恢复，快速失败限于受影响操作。

按资产、主体与信任边界选择最小必要权限和防护。安全配置缺失时拒绝受保护操作，真实凭据不进入代码或日志；prompt 不代替工具访问控制，不因安全口号增加未经论证的协议或服务。

## 实施与协作

按可用行为划分可集成增量，先验证可能推翻方案的风险。跨模块、公共接口或难恢复变更明确依赖和恢复办法；重构与功能变化尽量分开，保持范围内的既有保证。验收变更须作为需求决定，不能迁就实现。

并行前明确写入范围、共享契约、依赖和集成负责人；契约未定时先协调。文本合并成功后仍验证组合行为。

## 验证与证据

执行前明确目标对象与可观察的预期结果；执行后、依赖该结果继续或声明完成前，从目标文件、状态接口或实际产物回读并逐项比对。退出码、`ok`、`passed`、写入脚本自己的摘要不能单独证明后置条件成立。批量编辑核对全部预期修改及必要的原内容保留；原子操作失败时先确认整批未写入，不能假定部分已完成后继续下一批。

核验可以执行命令，关键是读取独立于写入摘要的目标状态，并检查返回的对象、范围、版本与内容，不是再获取一个成功标签。例如编辑后读取文件和差异，提交后检查提交对象与剩余工作区，构建后检查生成页面及链接。只读观察返回具体状态且覆盖预期条件后即可停止，不递归核验每条读取命令；空输出、对象或版本不符、结果矛盾时才换直接读法或最小复现。无法观察时标为未确认，不以反复重跑取得的成功摘要替代。核验强度随风险调整，不限于 tao 脚本。

断言来自需求、独立算例或性质，不复述实现。mock 可隔离非目标依赖，不能替代待验证的关键集成；缺陷尽量先复现失败，再确认同场景通过。低影响文案或格式修改检查受影响内容，不为仪式新增测试。

复用项目命令和门槛，区分原有失败与回归；反复且交付必需的检查固化到项目入口与已有 CI。不能靠削弱断言、跳过检查或偶然重跑掩盖失败；输入变化后按影响重验，无法判断则保守检查。执行与保存规则分别见 [验证规程](verification.md) 和 [证据保存](evidence-retention.md)。

度量服务具体决策，不套统一覆盖率或复杂度分数。区分实测、估算和风险信号；耗时、资源、可获取费用分别报告，代码行数不换算人日，估算费用不冒充账单。

## 调试与审查

保存现场、复现并提出可证伪假设，用区分原因的最小实验指导修复；连续修改没有新证据时调整方法。事故可先可逆止损，但缓解不等于根因修复。修复后验证原场景与相关回归。

正式审查按 [审查规程](review.md) 检查需求符合性和实现质量，意见须可定位，说明具体场景与解决要求。缺满足承诺的前提时选择补足、缩小或暂停，不把必要条件列为范围外后默认通过。

## 运行与演进

观测围绕成功判据、故障位置、影响和恢复选择日志、指标及关联标识。简单查询足够时不新增遥测系统。高影响发布验证停止、回滚和必要数据修复路径，按需小范围放量；代码回滚不等于数据恢复，运行观察反馈到后续取舍。

迁移检查真实数据、消费者、在途操作与可用性承诺，默认关闭不证明无存量。优先兼容扩展，破坏性变化明确支持窗口与退出条件；无存量约束不预建多阶段迁移，临时适配与开关有移除条件。

性能优化基于明确目标和代表性基线，定位瓶颈后在同等条件比较；回退无收益的复杂实现。没有需求或证据时不预加缓存、并发和分布式机制。

## 知识维护

行为变化同步权威规格、接口和操作说明；冲突时判断错误来源，不机械改文档迎合缺陷。长期决定保留理由、备选和后果，日常进度留在 plan，恢复摘要按 [工作流状态](workflow-state.md) 保存。

调试与收尾所得经验优先落到类型、约束、回归测试、静态检查或已有 CI；术语歧义补受控词汇，长期取舍归 design／ADR，操作陷阱归 runbook。文字只补充可执行约束未表达的原因、条件或恢复方法，没有新知识就不新建总结。更新限于项目授权范围，不改全局安装的 skill；删除过时和重复规则。
