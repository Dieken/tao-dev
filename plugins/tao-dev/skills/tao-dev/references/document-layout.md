# 文档组织

确定内容归属、文件位置、命名或拆分时读取。profile 与模板见 [文档规程](documents.md)；阅读目录见 [出版规程](publication.md)，记录和报告位置见 [证据保存](evidence-retention.md)。目录可按项目映射。

## 内容归属

| 内容 | 权威位置与组织单元 | 不放什么 |
|---|---|---|
| 产品规格 | `docs/product/<capability>.md`，每个用户可命名的能力一份；含目标、范围、REQ／UC、约束 | 本次施工步骤、执行日志 |
| 系统与模块设计 | `docs/engineering/<system-or-module>.md`，每个已有系统或模块一份；含边界、状态、接口与依赖 | 复制规格全文、日常任务 |
| 跨变更的技术决定 | `docs/engineering/decisions/<slug>.md`，每个 ADR 一份；含背景、备选、决定、后果 | 临时实现过程；只影响本次变更的选择留在计划 |
| 变更计划 | `docs/plans/<yyyy-mm>/<yyyymmdd>-<slug>.md`，一次交付目标一份 | 已在规格定义的需求全文、原始测试日志 |
| 用户说明 | `docs/user/<user-task>.md`，每个读者操作目标一份 | 内部研发任务 |
| 运维说明 | `docs/operations/<operation>.md`，每个部署、诊断或恢复操作一份 | 暂时实验记录 |
| 术语 | `docs/glossary.md`，项目共用；首次定义和同义词关系集中维护 | 复制各模块的全部接口定义 |

同一事实只在权威位置修改；变更直接更新长期规格与设计，计划引用 REQ／UC／ADR，说明本次差异及执行安排。代码与文档共同评审、集成，出版绑定发布版本。

`.tao/` 保存配置和 [工作流状态](workflow-state.md)，正式文档、任务和交接属于项目资产。缓存及短期输出按 [证据保存](evidence-retention.md) 管理。

## 日期、目录与文件名

长期文档使用稳定的语义文件名，不加日期或阅读序号。计划按创建月份放入 `docs/plans/<yyyy-mm>/<yyyymmdd>-<slug>.md`，月份固定两位；日期取 created 的本地日历日期，slug 用小写 ASCII 单词与连字符。附件沿用计划去掉 `.md` 的同名目录，位于同一月份，实际需要时才创建。编辑、移动或归档不刷新日期。

默认在篇下最多增加两层主题目录；已有子系统确需更深时在项目约定中说明。单目录直属正文超过 20 份时按已有能力、子系统或操作主题评估分组，每组至少两份；没有自然分组则保留并说明，不机械编号分桶。

ADR 默认平铺在 `docs/engineering/decisions/`，不按年月或状态归档。超过上述阈值时，先剔除应留在计划的局部选择，再按稳定主题评估 `decisions/<topic>/<slug>.md`；跨主题只选一个主位置，其他位置引用。被替代的决定保留记录及替代关系。

创建计划前检查同名计划与附件：同一事项继续原计划，新事项使用更具体的 slug。生成器不覆盖、不追加计数后缀。不同分支的同名计划若 CHG 不同，保留两项，调整其中一个 slug、附件和链接，正式 ID 不变。

## 文档与附件拆分

不改变行为、接口、权限、持久数据或运行约束的局部文案／格式维护可不建计划。其余变更采用 plan profile；完整功能开发的 spec、design、plan 分别有明确入口，优先复用已有权威文档。无设计变化时引用已有设计；用户明确要求合并时才按现有 profile 合并。

设计可先于计划写入预留附件目录。任务默认内嵌 plan，plan.design 只引用设计并说明必要实施约束。design_docs 可指向多份共享设计，专属设计可回指 CHG。拆分后原处保留入口和职责说明，定义与 ID 随内容移动：

| 触发条件 | 确定动作 |
|---|---|
| 单份计划超过 20 个正式 TASK | 将全部任务移到同名附属目录的 `tasks.md` |
| 一个决定约束至少两个变更，或改变系统级接口／数据／权限契约 | 抽取为长期 ADR；计划保留 ID 引用 |
| 已确定两个同时执行的编辑任务会写同一部分 | 在开始并行前按各自拥有的子系统拆成命名附件，并明确各自唯一写入者；仅有“可能并行”不触发拆分 |
| 计划仍超过 300 个非空源文件行 | 先拆超限任务，再把完整参考资料移成命名附件；不把单个 REQ／UC／ADR 拆开凑行数 |

这些是 tao-dev 的默认阈值。需要覆盖时在项目开发约定中写明数值与适用范围，agent 按该约定执行；当前 CLI 没有拆分阈值配置键。既有文档在修改涉及超限部分时再拆分；语义上不可再拆的条目记录例外理由。不能靠压成长行绕过阈值；日志过长时移出日志，不拆规格来容纳日志。
