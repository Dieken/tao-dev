# 正式对象退役

删除、替代正式对象或恢复中断的退役操作时读取。格式由 [注册表](../assets/document-profiles.json) 的 retirement_records 定义；普通移动、任务完成和功能弃用不自动触发退役。

## 选择与预览

可保留原定义并标记 retired，或移除定义并留退役记录，两处不重复定义。临时未索引草稿可直接删除。deprecation 表示不建议使用，迁移安排写在规格和使用说明中；retired 表示退出当前有效集合。

运行 `tao retire <ID> --reason <说明>` 只读预览；`--replaced-by <同类型 ID>` 可重复。核对移除对象、引用影响与诊断，在已有退役授权内加 `--apply` 应用。审查建议本身不授权删除；命令不自动改写消费者引用。

DOC、CHG 或 EVD 退役会移除定义该对象的整份文档，并为其中全部正式定义留记录；REQ／UC／ADR／TASK 移除对应完整条目。先调整会留下空必需章节、无需求规格、无任务计划、坏文件链接或重定向目标的文档，再重新预览。

## 记录与合并

记录默认保存到 `docs/retired/<yyyymmdd>.jsonl`，使用配置的 retired 目录并纳入 VCS。日期为实际退役的本地日期。每行一个 UTF-8 JSON 对象，包含 id、retired_on、非空 reason、replaced_by（同类型 ID 数组，无替代时为 []）；不含未知或重复字段、空白记录。文件日期与 retired_on 一致。

同一 ID 只保留一条记录；修正在原处完成，不追加事件。同日并发或分支合并后核对 ID 与替代关系，替代目标须可解析、非自身且无环。JSONL 不挂入 toctree，但参与全局查重与引用检查。

## 中断恢复

先核对源文档、退役记录和运行中的写入者，再以相同参数重试；保留原记录日期。相同记录可继续，原因或替代关系不同会报冲突。中间状态可能出现重复定义，不能隐藏诊断或覆盖矛盾记录。确认没有活跃写入者后才处理本次操作的遗留锁。

完成后执行文档检查；涉及已分享入口时按 [出版规程](publication.md) 构建并检查链接。无可还原历史基线时只能报告当前集合一致，不能声称已检查所有历史删除。
