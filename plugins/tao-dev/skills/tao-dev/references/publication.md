# 书籍出版与稳定链接

构建、分享或审查使用方项目的文档书籍时读取本文，用于选择正式链接和核对出版结果。`tao docs build` 使用 MyST、Sphinx 与书籍主题生成 HTML，并检查正式锚点及标题链接；源文件检查本身不能代替构建。日常编写使用 [文档规程](documents.md)。

篇、章、目录页与显式阅读顺序遵循 [文档组织规程](document-layout.md)。构建后核对目录层级、同级前后页、全部纳入页面的可达性与唯一主位置；排除的资料不应意外进入书籍。篇章分组是阅读语义，不保证任意主题或 PDF 构建器呈现相同版式；HTML 导航与 PDF 的篇章样式分别验收。不要把目录结构已经写好报告为书籍已经生成。

HTML 构建按根 toctree 的阅读顺序，为页面及内容章节显示层级编号；正文、左侧书籍导航和页内目录使用同一编号。navigation 页标题保留所在篇章编号，固定的导读和目录标题不编号。

编号只是可变的显示信息：不写回 Markdown 标题，不进入文件名、正式 ID、DOM `id`、引用片段或永久链接。移动或插入章节可以改变编号，不因此重编 ID、增加重定向或使原有 `href` 失效；分享和交叉引用继续使用下述稳定入口。PDF 是否显示相同编号需单独验收。

持久的正文条目引用使用 MyST need role：

```markdown
参见 {need}`REQ_<YYYYMMDD>_<16位随机串>`。
```

构建时，`{need}` 引用的可见链接文字取目标类型及索引中的标题或任务描述，ID 保留在 href 中；标题修改后显示文字随之更新，稳定入口不变。退役对象以退役说明作为引用文字，其说明页中的替代条目链接同样显示目标标题。索引没有可用标题时才回退为 ID。标题按纯文本安全渲染，支持项目所用语言；不替换作者在普通 Markdown 链接中明确指定的文字。

关系字段和任务中的 ID 列表也是正式引用。文档标题下按结构化关系生成“关系／类型／文档”表，包含前向和反向入口；内嵌任务链接到计划任务节。任务的 relates、depends_on 和条目的关联字段显示可点击的类型与标题，不展示原始 ID 数组。关联表不写回源文件，无关系时不生成空表。普通文件导航使用标准 Markdown 链接；可分享的正式条目与章节必须使用由稳定标识生成的锚点，不能依赖标题文字自动生成的 slug。代码注释引用完整条目 ID，由工具解析到正式位置；不要求在每个函数重复标注任务。

出版契约如下：DOC 首页锚点为完整 DOC ID；REQ／UC／ADR／TASK 等条目使用其完整 ID；二级章节使用 `<DOC-ID>--<section-key>`。当前固定章节键覆盖 profile 中的二级章节；更细的内容需要独立分享时，使用正式条目 ID，或拆成独立文档的固定章节，不把自动标题 slug 宣称为永久标识。条目标题已有条目 ID 时不再分配第二个标识符。普通排版小标题可保留自动锚点，但不能把它作为正式永久链接。

源文中的章节键与条目定义是唯一维护位置。标题旁的链接按钮及“复制链接”操作必须给出稳定目标；启用主题的自动标题链接不等于已经满足此要求，不另维护一份可能漂移的锚点清单。

稳定锚点不能单独解决文件移动。书籍需生成固定入口 `refs/<ID>.html#<ID>`，章节入口使用同样规则附加稳定章节键，由索引指向当前页面；复制链接优先给出此入口。移动条目只更新解析位置。当前支持保持 DOC ID 的文件改名、移动及标题修改；章节跨 DOC 移动时，按下述配置为旧固定入口生成重定向。退役对象生成说明页；针对历史版本的链接保留版本路径。发布域名及书籍根路径变化仍需站点迁移重定向，不能承诺仅靠 ID 自动解决。

验收必须实际构建 HTML，检查正文标题、左侧书籍导航和页内目录使用同一章节编号，并检查 DOM 中的唯一锚点、引用文字与复制链接。再改标题、移动文件或调整目录顺序并重新访问旧入口；显示编号可随目录改变，`href` 不得包含该编号。不得以 Markdown 含有 ID、toctree 已配置或只看到正文编号作为通过。源文件托管平台的自动标题链接不等同本书籍的永久链接。

## 跨文档章节重定向

agent 移动已分享的章节内容时，在 `.tao/config.toml` 的 documents.section_redirects 中记录旧章节到当前章节的映射，再执行 `tao verify --only docs` 和 `tao docs build`。这是书籍入口的工具配置，不新建一套文档或对象 ID。格式为：

```toml
[documents.section_redirects]
"<旧 DOC-ID>--<旧章节键>" = "<当前 DOC-ID>--<当前章节键>"
```

写入时用实际存在的 ID 和稳定键替换示例；键和值必须采用完整 DOC ID 加 `--` 加章节键。旧 DOC 必须仍在源定义或退役记录中，目标必须是当前管理文档中的实际二级章节。直接指向最终位置，不允许自指、循环或多跳重定向；内容再次迁移时同时更新已有映射，避免累积跳转链。旧章节不继续维护第二份正文：按文档契约保留简短指向说明，或退役不再需要的旧文档。

构建器在旧 `refs/<DOC-ID>.html#<DOC-ID>--<章节键>` 入口按片段跳转，即使旧 DOC 已退役也保留该能力。目标页面路径由当前索引推导，文件改名不需要改映射；链接文字使用目标文档和章节的实际标题，适应项目语言。未启用 JavaScript 时仍提供普通链接供阅读者打开目标。重定向只保护书籍固定入口，不使已经删除的原始 Markdown 路径、外部托管平台自动锚点或旧域名自动可用。

配置目标丢失、类型错误和重定向链会使文档检查失败；构建失败保留上一次书籍。退役命令也检查这些关系，不能移除仍作为重定向目标的文档。分享前实际访问旧入口；配置存在本身不能证明已经构建、部署或获得历史链接保留保证。

## 构建和保存

按 [运行环境规程](runtime.md) 在已有授权内执行 `tao setup`，准备核心环境和使用 [锁定出版依赖](../scripts/requirements-publication.txt) 的独立出版环境；配置 documents.book_root 后运行 `tao docs build`。构建本身不安装依赖；出版环境缺失不影响核心检查。输出位于配置的 temporary 目录下的 book/，默认 tmp/tao/book/；首页位置以 JSON 输出 index 为准。HTML、构建日志和缓存默认不纳入 VCS。发布到外部站点是另一项需要明确授权的操作。

构建使用同一个源校验器和条目索引，不再维护第二份需求索引。Sphinx 警告按失败处理，生成后检查锚点唯一性和永久入口；失败保留上一次可用书籍。已有输出的 refs/ 用作删除基线，已出版 ID 必须保留定义或退役记录。首次构建或清空临时输出后没有该基线；长期发布应保留上一版本入口用于删除审查，不能把临时缓存当成历史记录。PDF 和跨版本站点重定向不在当前实现范围。
