# 书籍出版与稳定链接

构建、分享或审查使用方项目的文档书籍时读取本文，用于选择正式链接和核对出版结果。`tao docs build` 使用 MyST、Sphinx 与书籍主题生成 HTML，并检查正式锚点及标题链接；源文件检查本身不能代替构建。日常编写使用 [文档规程](documents.md)。

篇、章、目录页与显式阅读顺序遵循 [文档组织规程](document-layout.md)。构建后核对目录层级、同级前后页、全部纳入页面的可达性与唯一主位置；排除的资料不应意外进入书籍。篇章分组是阅读语义，不保证任意主题或 PDF 构建器呈现相同版式；HTML 导航与 PDF 的篇章样式分别验收。不要把目录结构已经写好报告为书籍已经生成。

持久的正文条目引用使用 MyST need role：

```markdown
参见 {need}`REQ_<YYYYMMDD>_<16位随机串>`。
```

构建时，`{need}` 引用的可见链接文字取索引中目标条目的标题或任务描述，ID 保留在 href 中；标题修改后显示文字随之更新，稳定入口不变。退役对象以退役说明作为引用文字，其说明页中的替代条目链接同样显示目标标题。索引没有可用标题时才回退为 ID。标题按纯文本安全渲染，支持项目所用语言；不替换作者在普通 Markdown 链接中明确指定的文字。

关系字段和任务中的 ID 列表也是正式引用。普通文件导航使用标准 Markdown 链接；可分享的正式条目与章节必须使用由稳定标识生成的锚点，不能依赖标题文字自动生成的 slug。代码注释引用完整条目 ID，由工具解析到正式位置；不要求在每个函数重复标注任务。

出版契约如下：DOC 首页锚点为完整 DOC ID；REQ／UC／ADR／TASK 等条目使用其完整 ID；二级章节使用 `<DOC-ID>--<section-key>`。需要独立分享的下级章节也分配稳定键，键在文档内唯一，不从标题动态推导。条目标题已有条目 ID 时不再分配第二个标识符。普通排版小标题可保留自动锚点，但不能把它作为正式永久链接。

源文中的章节键与条目定义是唯一维护位置。标题旁的链接按钮及“复制链接”操作必须给出稳定目标；启用主题的自动标题链接不等于已经满足此要求，不另维护一份可能漂移的锚点清单。

稳定锚点不能单独解决文件移动。书籍需生成固定入口 `refs/<ID>.html#<ID>`，章节入口使用同样规则附加稳定章节键，由索引指向当前页面；复制链接优先给出此入口。移动条目只更新解析位置。当前支持保持 DOC ID 的文件改名、移动及标题修改；章节跨 DOC 移动的别名机制尚未提供，应保留原章节入口并链接到新位置。退役对象生成说明页；针对历史版本的链接保留版本路径。发布域名及书籍根路径变化仍需站点迁移重定向，不能承诺仅靠 ID 自动解决。

验收必须实际构建 HTML，检查 DOM 中的唯一锚点、引用文字与复制链接，再改标题、移动文件并重新访问旧入口；不得以 Markdown 含有 ID 作为通过。自动测试覆盖标题更新、特殊字符、改名、退役说明及失效删除；源文件托管平台的自动标题链接不等同本书籍的永久链接。

## 构建和保存

在项目已有 Python 环境中准备 [可选出版依赖](../scripts/requirements-publication.txt)，配置 documents.book_root 后运行 `tao docs build`。未安装依赖时报告缺口，不自动安装。输出位于配置的 temporary 目录下的 book/，默认 tmp/tao/book/；首页位置以 JSON 输出 index 为准。HTML、构建日志和缓存默认不纳入 VCS。发布到外部站点是另一项需要明确授权的操作。

构建使用同一个源校验器和条目索引，不再维护第二份需求索引。Sphinx 警告按失败处理，生成后检查锚点唯一性和永久入口；失败保留上一次可用书籍。已有输出的 refs/ 用作删除基线，已出版 ID 必须保留定义或退役记录。首次构建或清空临时输出后没有该基线；长期发布应保留上一版本入口用于删除审查，不能把临时缓存当成历史记录。PDF、跨版本站点重定向及跨 DOC 的章节别名不在当前实现范围。
