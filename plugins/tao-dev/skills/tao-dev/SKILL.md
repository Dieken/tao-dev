# tao-dev · 协作开发之道

围绕可验收的用户结果开发，选择简单方案，保存真实进度和可核实的交付依据。

相对 Markdown 链接以所在文件为基准解析；配套资源均位于本 skill 内。

## 开始工作

必须先读取 [流程操作](references/workflow.md) 的入口与当前动作段，按项目状态和已有授权推进。需求、设计、代码实现（包括局部修复）、调试或审查必须在行动前读取 [工程规程](references/engineering.md)；只读 `status` 和仅执行 `docs` 本地构建时，无需完整读取 `references/engineering.md`。

## 按任务读取

| 当前工作 | 读取入口 |
|---|---|
| 创建、修订或审查正式文档 | [文档规程](references/documents.md)，涉及的章节及当前模板 |
| 涉及 tao 概念、受控命名或用词冲突 | [tao 术语](references/glossary.md) 与项目相关定义 |
| 正式审查 | [审查规程](references/review.md) |
| 调用 CLI 或配置项目 | [工具规程](references/tools.md)，再按操作进入 setup、状态、验证或运行环境接口 |

只读取当前任务相关小节与模板；动作、局部维护边界及授权统一见 [流程操作](references/workflow.md)。

用户决定目标、预算和风险；已有授权内自主推进。完成声明以实际执行为据，说明过期证据、能力缺口与阻断，按流程采用可用替代。

tao 的检查、状态记录或导入成功，只说明其覆盖范围内的观察，不构成验收、授权、结论正确或身份证明；各规程只在有具体错误推断时单独说明例外。
