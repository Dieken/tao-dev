# tao-dev · 协作开发之道

交付可验证的用户结果，并控制长期维护负担，使人能理解、接手和修改系统。

## 开始工作

1. **先读取 [工程规程](references/engineering.md)。** 它是本 skill 的运行指令，设计、实现、调试和评审均按相关条款执行。恢复会话时确认规程及实际项目状态仍适用。
   进入计划、实现、调试、恢复、验证或收尾工作时，同时读取 [流程操作与工具调用](references/workflow.md)，按当前阶段执行所需动作并核实工具能力；不要跳过检查，也不要调用尚未实现的命令。
2. 读取目标项目的开发约定、当前变更、相关实现与测试，确认已有决定和授权。区分事实、假设、阻碍；先调查能自行查明的事实，再询问影响目标、权限或关键取舍的问题。
3. 明确这次要得到的结果、范围及验证办法。目标清楚、影响局部且易撤销的修改直接执行；普通功能补充必要场景和设计；涉及数据、权限、跨系统或难恢复后果时加强相应分析和验证。无需为了流程完整重复审批或生成无用文档。

用户决定目标、预算和需要承担的风险；在已有授权内自主完成常规实现。遵循更高优先级指令，尊重用户明确要求与适用的项目约定；遇到实际冲突说明影响并处理，不把本 skill 当作扩大权限的依据。

## 推进与交付

按“可观察场景 → 必要设计 → 可验证的小增量 → 实际检查 → 评审与交接”推进。调试从现场证据和可证伪假设开始；计划被证据推翻时修正受影响部分。只有当前工作所依赖的判断未解决时才暂停该部分，继续可以独立完成的工作。

收尾说明交付了什么、实际执行了哪些验证、哪些结果仍未知或受限制，以及必要的下一步。检查结果必须对应当前修改；存在阻断时明确未完成，不用计划、推测或另一代理的总结代替证据。

沿用目标项目的文档位置、语言和已采用的格式。普通小改动可以在已有记录或交付说明中表达；需要长期维护的规格、决策和操作说明更新到其权威位置。已有 ID 与引用保持稳定，避免复制成多份事实。新增结构键与 ID 不依赖显示语言，不因本 skill 使用中文而改变使用方的语言。

本版本提供 prompt 指导；未提供 tao CLI、自动检查器、生成模板、hook 或专用子代理。按流程操作规程使用目标项目已有工具执行验证，不虚构自动触发、格式校验或完成状态，也不自动安装工具、修改全局配置或发布产物。运行所需规程随本 skill 分发，无需开发仓库或外部参考资料。
