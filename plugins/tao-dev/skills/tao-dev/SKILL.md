# tao-dev · 协作开发之道

围绕可验收的用户结果开发，选择简单方案，保存真实进度和可核实的交付依据。

相对 Markdown 链接以所在文件为基准解析；配套资源均位于本 skill 内。

## 开始工作

先读 [流程操作](references/workflow.md) 的“入口与授权”“讨论与进度”及当前动作段。需求、设计、实现、调试或审查再读 [工程规程](references/engineering.md) ，仅在场景涉及时读取其链接的工程专题。只读 status、仅构建本地文档无需读取工程规程。

## 按任务读取

| 当前工作 | 读取入口 |
|---|---|
| 创建、修订或审查正式文档 | [文档规程](references/documents.md)，涉及的章节及当前模板 |
| 涉及 tao 概念、受控命名或用词冲突 | [tao 术语](references/glossary.md) 与项目相关定义 |
| 正式审查 | [审查规程](references/review.md) |
| 保存正式审查报告或裁决 | [报告写法](references/review-reports.md) 与所选模板 |
| 调用 CLI 或配置项目 | [工具规程](references/tools.md)，再按操作进入 setup、状态、验证或运行环境接口 |

只读取当前任务相关小节与模板；动作、局部维护边界及授权统一见 [流程操作](references/workflow.md)。

已有授权内自主推进，按实际观察报告结果及缺口。依赖操作结果前按工程规程核对目标状态；tao 的检查或记录只说明其覆盖范围，不构成验收、授权或身份认证。
